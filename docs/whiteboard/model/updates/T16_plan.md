# T16 实施计划 · 动画全量按元素库标准重做

日期：2026-11-01。立项：用户拍板「动画全部重做，按这个标准来」。
标准：元素 = 部件 + 枢轴 + 锚点 + 参数的数据定义（样板 `model/props/teapot.yaml`），场景只许按 id+锚点名引用元素；动作基元吃锚点算几何并自带构建期断言；几何一律由定义内坐标实算，禁止手填测得值。
范围界定：**只动渲染层**（元素/基元/模板），不动内容层——台词、ITEMS、知识模型沿用通宵班成果（见 §5）。盘点依据：`T16_element_inventory.md`。

## 0. 总原则

1. **定义先行**：任何元素先在 `model/props/` 立定义（人物同格式，kind=character），渲染侧同步副本进 `v5/props/props.js`，按 version 对账；模板内私绘、私存几何一律禁止。
2. **断言随基元走**：基元自带构建期断言（只引锚点/参数），断言不过 = 停建，不许绕过。
3. **内容零漂移是硬门**：每幕重生成前后 ITEMS 逐条比对，漂移即停单（口径同 B6/B8）。
4. **分段验收、随时停单**：每段有独立验收门；遇「定义表达不了的演法」「与模板槽位/整体框架冲突」先停单登记，不强套（纪律同 T12）。
5. **环境现实**：构建与密帧复验依赖本机 Chrome 恢复；恢复前只推进源码层与 node 级断言自测，恢复清单与各批待验项挂账，完成口径以「构建+校验通过」为准，不以「源码已改」充数。

## P0 样板段（先证明格式与基元，再谈量产）

**输入**：茶壶元素（已落地：`model/props/teapot.yaml` + `v5/props/props.js`，记录 `PROP_lib_teapot.fixed`）；boundedness 家族四幕现行模板与 spec（`model/specs/boundedness_1..4.yaml`）；盘点 §4 优先序。
**产出**：
1. **Linda 单人绑定试点**：`model/props/linda.yaml`——分件（头/躯干/臂/腿）+ 部件枢轴 + 锚点（hand/gaze/footL/footR/headTop）+ 姿态集 profiles（standing/pointing/holdingCup/pouring 等以 boundedness 四幕实际需要为准）；皮肤令牌与几何分离；替换 fp 家族现行模板内嵌位图姿势（双轨归一）。
2. **核心基元六件**（引擎侧共享模块，参数吃锚点）：`pour`（由茶壶剖面抽出为独立基元：倾角反算、出流窗派生、液柱原点=tipAt、断言净下倾）、`cut`（切面锚点 + 两半守恒构造）、`fill`（液面锚点 + 满溢界断言）、`tear`（撕裂线基元；无存量场景，先立基元与断言样例，不强行找幕）、`hold` 家族（hold/give/take/put 同族参数化：手锚点↔物锚点对位、落点锚点）、`point`（手指锚点 + 视线锚点双对位）。
3. **杯元素**（道具优先序第 2）：`model/props/cup.yaml`（杯口/液面锚点），与 pour/fill 基元咬合。
4. **元素注册表校验门**：生成器侧检查——场景引用的元素/锚点/帧必须在注册表存在且语义名与内容相符（治 §盘点 坑 7/8：缺帧、空包构建期报警，不再靠开工抽查）。
5. boundedness 四幕全部改走新元素+基元重生成（spec 不动内容、只换模板引用），作为端到端验证场。
**验收门**：
- 四幕构建 + insightcheck/等效校验不合格 0；
- 全部基元断言在四幕真实触发路径上通过，且每条断言有一次**负面测试**（故意改坏参数必须抛错停建——茶壶样板已示范此法）；
- ITEMS 与现行定稿逐条零漂移；
- 密帧抽检：四幕全量密帧（旗舰口径），逐帧核锚点类问题（嘴轴、液柱原点、手-杯对位、视线落点、切面两半）；
- **用户质量门（量产前置）**：新旧同屏对比交付用户，用户有一票否决——不过此门，P1 不得启动。
**停单条件**：Linda 分件造型达不到现行画风一致性（用户质量门否决同理）；某基元在四幕中出现定义表达不了的演法（登记缺口，先扩定义格式再继续，不在场景里打补丁）；ITEMS 出现非预期漂移。

## P1 按模式推广（存量 552 幕的主体）

**输入**：P0 定版的元素格式、基元库、注册表校验门；现有 **323 份 spec**（B6/B8/B9/B10/B11 单源化存档）与各模式模板（auto/hd_g、oral、poly、mindmap、frBuild 及小 builder）；B10/B11 的 36 幕 spec 存档。
**产出**（逐模式一批，每批独立销账）：
1. 每模式一张「元素模板」：该模式的展品/人物出演改走元素引用；道具按盘点优先序逐批立定义（刀+被切物、书、箱子、门、灯/水龙头、球……），静物/符号类 emoji（树、太阳、💡 提示符等）立「符号豁免」清单——只登记、不元素化，避免过度工程。
2. **人物过渡形态「位图元素化」**：P1 不做全卡司绑定；先把 cast 位图帧登记为元素定义（帧 = 一种 skin，补锚点近似标注 + 脚底基线统一口径），并**订正注册表语义坑**（l_stand/l_read/l_coff 等按内容改名或加警示字段，引用端同步）——使 P1 的基元能以锚点方式调用人物（手/视线先用帧级锚点），P2 再换真绑定，场景引用不改。
3. 从现有 spec 批量重生成全模式场景（内容不动、只换渲染引用）。
**验收门**（每批）：
- ITEMS 零漂移（硬门，同 B6/B8 口径）+ ACTS 结构不变；
- 构建 + 等效校验不合格 0；
- **新增视觉门**：该批涉及的基元断言全过（含负面测试抽查）；密帧抽检——每批首幕全帧、其余幕 ≥20% 抽检（旗舰幕全检），抽检表逐项对锚点（接触/指称/守恒/液面）；
- 注册表校验门全过（无缺帧、无未登记引用）。
**停单条件**：某模式出现模板槽位与元素剖面冲突（登记为模式缺口，整批停、逐幕裁定，不逐幕打补丁）；ITEMS 漂移；抽检发现系统性锚点错位（回基元层修，不逐幕修）。

## P2 全卡司绑定 + 手写残部 + 长尾

**输入**：P1 定版的位图元素注册表与各模式元素模板；Linda 试点格式（P0 定版）。
**产出**：
1. **全卡司分件绑定**：Leo（457 幕，先行）→ Mia（196 幕）→ missw/mom/dad → grand/wang/通用人物（单帧角色可只立静态元素 + 锚点，不强求动作集）；动物/交通工具按出场面立锚点（车门、落点）。位图 skin 保留为可选皮肤（画风过渡），几何与锚点归定义。
2. **38 手写幕逐幕处置**（约数：B10/B11 存档 36 幕 + wo_grimm_voiceless_1 等停单/变体幕；开工时按 T12 台账逐幕核对销账）：逐幕三路裁定——并入模式元素模板 / 定点换元素 / 保留手写但元素引用合规化，并逐幕补齐事实表存档（B6/B10 挂账的占位事实表在此结清）。
3. **长尾道具**：纸（tear 基元配对）、瓶、及其余盘点长尾；vv 万能动词剧场的帧演义项逐组映射到 hold 家族基元参数（34 组，帧演面最大的一块基元存量）。
**验收门**：全卡司幕构建+校验不合格 0；人物锚点断言（手-物对位、视线落点、脚底不漂移）抽检口径同 P1 视觉门，人物幕抽检率 ≥30%；手写幕逐幕有处置记录与事实表；全库注册表校验门全过（至此模板私绘/私存几何零残留，以扫描口径验收）。
**停单条件**：角色绑定画风一致性不达标（回 P0 格式层复议，不逐角色硬凑）；手写幕独特演法与元素格式冲突（保留手写并登记为格式缺口，提请主会话裁定）。

## 5. 与在途工作的关系（写死，避免互相踩）

- **B10/B11（已完）**：其内容层成果（323 份 spec 存档、ITEMS 定稿、已裁定订正、36 幕处置记录）**直接复用**为 P1/P2 的输入；T16 只换渲染层，若发现内容层问题，只登记、不顺手改（内容变更另走裁定流程）。
- **T15 载荷包**：现行包基于旧模板打包，**作废待重打**——待 T16 各模式模板定版后，按最终模板重打包（payloads 口径与一键批处理脚本设计不变，脚本仍为用户本地双击执行）。P0/P1 期间不再动主文件。
- **回灌**：整体排在 **T16 全量重做之后**（回灌对象 = 重做后的最终动画），批处理三件套在回灌启动时一并交付。
- **茶壶/元素库（已落地）**：即 P0 第 0 项，不重复立项；本计划 P0 自 Linda 试点起步。
- **推送**：主 HTML 与 JPG 的 GitHub 推送路径仍待用户选路（网页上传/拆分），与 T16 并行不悖，等回灌版主文件产出后一并处理。

## 6. 段间依赖与顺序

P0（样板+用户质量门）→ P1（逐模式：建议序 auto/hd_g → poly → mindmap → frBuild/小 builder → oral（幕数最大、对话帧演为主，元素收益在 hold/point，排模式末位））→ P2（卡司与残部）→ T15 重打包 → 回灌。每段验收门不过，不进下一段。
