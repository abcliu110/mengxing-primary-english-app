日期：2026-11-01。性质：只读盘点（全库源码 + 精灵库扫描，未改任何场景）。
格式基准：元素定义样板 `model/props/teapot.yaml` 文件头注释（kind=prop|character；parts 各带 pivot/anchors；skin 与几何分离；params 给 design+computed；assertions 只引锚点与参数）。

## 0. 口径说明（先读）

- 场景文件实测（`v5/scenes/*.js`，剔除共享库 auto/oral/poly/adj_train）：**875 个文件** = 规范源 **558** + 单源化生成副本 `gen_stock_*` **283** + T11 生成幕 `gen_*` **34**。规范源 558 与台账「577 幕」（552 存量 + 24 原理 + 1 变体）的差额是模板/变体的一对多文件对应（fp 模板 26 个文件对应 24 幕原理家族等）。
- 下文人物/道具/动作的幕数均为 **558 规范源口径**（已剔副本，避免重复计数）；个别注明「文件口径」者为 875 口径。
- emoji 计数是源码内字形出现幕数，**混合三种身份**：台词提及、界面符号（如 💡 多为「要点提示」符，非实物灯）、实物出演。因果道具的优先序不单看此数，另按因果敏感度校正（见 §4）。
- 动作幕数是台词字符串内动词提及的**下限估计**：大量动作由帧演而台词未提（vv 万能动词剧场尤甚），帧演面在 §3 单独注记。

### 已知语义坑（帧名与内容不符 / 内容未经核验类）

1. **`l_stand` 名「站」实为坐姿**（布局 QA 登记；文件口径 76 个文件引用 `l_stand`）——按名取帧即播错姿势，是人物版「壶嘴 65.9°」。
2. **`l_read` 帧内自带课桌**：物件混入人物帧，人物移动时桌子跟人走（文件口径 10 个文件引用）。
3. **`l_coff0–2` 帧名像 coffee、实为 coat-off（脱外套）**；且 `l_coff0` 又被布局 QA 定为「干净站姿参照帧」——命名与内容双重误导。
4. **`m_read` 是坐着读**（CAST 明注）：场景需要「站着读」时无帧可用，只能错用或静默换姿。
5. **位图帧内容残留邻帧/缺件有前科**：V31 `l_lift1/2` 曾带邻帧杠铃片与举重人残影、V34 `missw_give` 曾缺下半身、V30 灯塔残留，均为 2026-10-31 返工逐帧修补——证明 cast 帧从未经系统性内容核验，同类问题只能按「未核验」对待全库。
6. **手工切帧质量参差**：`l_ex0–2`（早操）、kite/picnic 联排为手工分割，锚点（脚底基线）无统一口径，跨帧跳位靠模板硬调。
7. **引用与库不一致无报警**：`wo_grimm_voiceless_1` 引用的 `l_point`/`l_think` 在共享库 `wogr1.js` 中缺失，B6 因此停单——引用端写了不存在的帧，构建期无人拦截。
8. **精灵库完整性无校验门**：B10 开工前发现 15 个精灵库在克隆中缺失（14 个空包 + `hdg18_1` 现场重建），库文件缺失/为空只能靠开工抽查发现。
9. **Linda 双轨**：fp 家族 Linda 姿势是模板内嵌位图集（姿势语义靠模板注释），与 cast 的 Leo/Mia 体系互不注册——同一「人物」概念两套事实源。

## 4. 元素建设优先序（出场频次 × 因果敏感度）

**人物**：① Leo（457 幕，因果面最大；但全绑定最贵——P1 先做「位图元素化」登记锚点，P2 换绑定，见计划）→ ② Mia（196 幕）→ ③ Linda（幕数少但为原理家族主讲 + P0 试点，序列上最先动手）→ ④ missw（29）→ ⑤ mom/dad（13/7）→ ⑥ grand/wang/通用人物（P2 长尾占位）。
**道具**：① 茶壶（已落地）→ ② 杯 → ③ 刀 + 被切物（苹果/面包/蛋糕）→ ④ 书 → ⑤ 箱子/门（容器与转轴族）→ ⑥ 灯/水龙头（状态族）→ ⑦ 球 → ⑧ 纸/瓶（长尾）。
**基元**：① pour（样板已部分落地，P0 补全为独立基元）→ ② hold 家族（hold/give/take/put 同族参数化）→ ③ point → ④ cut → ⑤ fill → ⑥ open/close → ⑦ walk → ⑧ kick/throw/catch → ⑨ tear（无存量，最后）。

—— 盘点方法与原始计数：全库正则扫描（cast 帧名引用、emoji 字形、台词动词），脚本口径如 §0；原始扫描结果由执行会话留存，可按同口径复跑核对。
