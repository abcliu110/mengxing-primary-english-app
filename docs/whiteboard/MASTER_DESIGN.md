## 2. 17 条决策 → 落地设计

### 决策 1　格林定律（真格林定律 + 吸收 vowel_shift）
- **放哪**：📖 单词身世总枢的一章「格林定律」。
- **内容**：真格林定律（辅音成体系挪位：p→f、t→th、k→h…，foot ↔ pedal）按 `grimm_law/DESIGN.md`；原 `vowel_shift` 页签的 3 个案例（foot→feet、food→feed、safe→save 等）**整体并入**为「元音变异（i-mutation）」小节，名字改正（不再叫「格林音变律」）。
- **合并步骤**：新章验收通过 → 实验室里删 `vowel_shift` 页签（入口卡片、`TABS`/`READY` 登记、`cases/vowel_shift.js` 移到新章文件、`GRIMM_VOWEL_LAWS` 数据迁移）→ 所有跳到 `vowel_shift` 的链接改指新章。HANDOFF §4 里记的 vowel_shift 讲法问题（blood 不是 /uː/、life→live 元音也变等）在迁移时一并改正。

### 决策 2　中英对照总枢（新开）
- **放哪**：首页新开「🔀 中英对照总枢」，和第一性原理、单词身世并列。
- **内容**：A 中英思维对照（句子必须有主语、修饰语位置、形合 vs 意合、单复数和时态必须上身、「是」≠ be）+ Q 否定疑问 Yes/No + 正迁移「这些你已经会了」（先讲一样的，再讲不一样的）+ N 一字多词（借、说、穿、带、教/学）+ M 代词变格活化石。
- **从第一性原理搬迁（用户 2026-10-29 已确认：搬 ④-1、⑥-1；⑥-2、⑥-3 留在第一性原理；③-1、③-4 留下）**：
- **搬迁零丢失（用户硬要求）**：原幕的全部镜头、画面元素、例句、朗读、旁白、徽章、出处、小测/预测题、跳转入口原样搬过去，只允许增加不允许删减；搬之前先导出原幕「内容清单」（逐镜头列出词、句、朗读、道具），搬完逐条对照，新位置全部通过验收后才删原幕；原幕位置留一个跳转到新位置的入口。

### 决策 13　按需加载（仍然双击即用）
- 目标：点到哪个模块才载入哪个模块；**仍是单个 HTML、双击就能用，不需要服务器**。
- 方案：
  1. 每个模块的白板脚本（`cases/*.js`）写成不执行的 `<script type="text/plain" id="wbmod-<模块>">`（可选再压缩成 base64 + gzip，浏览器用 `DecompressionStream` 解压，不支持时退回不压缩版本）。
  2. 第一次进入模块时 `wbLoadModule('<模块>')`：取出文字 → 生成 `<script>` 执行 → 登记 `WB_LAB`；之后不再重复加载。
  3. 大数据（如 `VOCAB_DB` 以外的模块数据）同理分块；首页只载入首页需要的部分。
  4. `insert_wb.py` 负责打包；验收加「首屏可交互耗时」对比（Playwright 记录，前后不能变差）。
- 不用 `fetch` 读外部文件（`file://` 下会被拦），所以全部内容仍在同一个 HTML 里。

## 2.5 视觉标准（商业级白板）——决策 18

> 目标：从「能讲明白」升级到「像商业级白板课一样好看」。**全部仍是离线单文件、双击即用**：不引外部字体、图片、音频文件或库；图形用 SVG 路径，音效用 Web Audio 现场合成（或极小的内嵌数据）。
> 逐条验收项见 `SOP.md` §9；做法细节见 `SOP.md` 视觉标准一章。

| # | 标准 | 设计要点 | 现状（db13720） |
|---|---|---|---|
| V1 | **手拿马克笔，跟着笔尖画** | 画线、写字时手和笔尖严格贴着当前笔画走；动效进行时手退到右下角；换下一笔时手平滑移过去，不瞬移 | 已有基础（手跟笔尖、平滑跟随），要复查镜头缩放时的位置 |
| V2 | **笔触有粗细和起收笔；重点词用荧光笔底色** | 线条中段略粗、起笔收笔略细（用两层描边或分段线宽模拟）；重点词下面先刷一道半透明荧光底色（黄 / 绿），再写字 | 线宽均匀；重点用圈和下划线 |
| V3 | **统一调色板、字号层级、留白网格** | 调色板 = 墨黑 `#1f2937` + 3 个强调色：红 `#e11d48`（错误 / 术语）、绿 `#059669`（正确 / 结论）、蓝 `#2563eb`（主角词 / 词根）；灰 `#64748b` 只用于注释，荧光黄 / 绿只作底色。字号 4 级：标题 32 · 小标题 22 · 正文 18–20 · 注释 13–15。版面 12 列网格（列宽 70、边距 24），元素对齐网格，四周至少 24 px 留白 | 旧案例用了 8 种颜色；新幕起按新调色板，旧幕在「升级」时统一 |
| V4 | **按动作类型用不同缓动；错开出场；镜头不硬切** | 出现 = 弹入（轻微过冲后回位）；吸附 = 回弹；移动 = 缓入缓出；退场 = 快出。同一组元素依次错开 0.08–0.15 秒出场；镜头切换一律用推拉 / 平移，不允许画面瞬间跳变 | 只有一种 ease；镜头已能推拉 |
| V5 | **画面与朗读对齐** | 读到哪个词，朗读条上哪个词高亮，**白板上同一个词也同时高亮**（荧光底色闪一下）；读的时候画面停住 | 朗读条逐词高亮已有；白板上的词还不会同步亮 |
| V6 | **讲解员小人多姿态 + 朗读口型** | 姿态：指、惊讶、举卡、翻书（另有想、欢呼）；朗读时嘴巴开合跟着朗读节奏；形象先给用户看（决策 16） | 未做 |
| V7 | **音效**（马克笔沙沙、弹出、答对「叮」） | Web Audio 合成，几 KB 以内；控制条一键静音（和朗读开关分开），默认音量低，朗读时音效自动压低 | 未做 |
| V8 | **擦除式转场 + 统一片头和收尾金句卡** | 镜头之间用板擦擦掉（擦痕扫过、内容跟着消失），不是直接淡出；每幕统一片头（标题卡 + 徽章 + 5 步进度条）和收尾金句卡（一句话洞见 + 口诀，可截图复习） | 镜头之间是淡出；片头是标题 + 进度条，收尾是总结图 |

**实施方式**

## 2.6 人物动作库（决策 19）

> 规则 R4：句子里有动作词，画面上就要有人做这个动作，和朗读同步（读到 carry，小人正在搬）。
> 演员：讲解员小人（决策 16，形象待用户确认）或场景角色（搬运工、旅客、公主……），都用同一套简笔骨架，所以动作可以共用。

**骨架**：圆头 + 躯干 + 两段式手臂（上臂、前臂）+ 两段式腿（大腿、小腿），关节用角度描述；一个「姿态」= 一组关节角度，一个「动作」= 几个姿态按时间插值（全部是时间 t 的函数，进度条拖到哪都正确）。可以拿道具（箱子、卡片、书、文书），道具挂在手上跟着走。

**动作库 v1（可复用、可扩展）**

| 动作 | 用在什么词 / 句 | 关键姿态 |
|---|---|---|
| 走 walk | go、come、walk、pass through | 左右腿交替迈步 + 手臂摆动，整体平移 |
| 跑 run | run、hurry、race | 步子更大、身体前倾、手臂弯曲大幅摆动 |
| 搬 carry | carry、port「搬运」、import / export / transport | 弯腰抱起箱子 → 直起身 → 抱着箱子走 |
| 拿 take | take、get、pick up | 伸手 → 握住 → 收回胸前 |
| 放 put | put、put down、put away | 手往前下方伸 → 松手 → 物体留在原处 |
| 指 point | look、this / that、here / there | 一只手伸直指向目标，头转向目标 |
| 举 hold up / lift | hold up、lift、show、support（从下面托住） | 双手举过头 / 托在物体下面 |
| 跳 jump | jump、hop | 下蹲 → 腾空 → 落地回弹 |
| 转身 turn | turn、turn around、turn back | 身体左右翻转（镜像） |
| 挥手 wave | hello、goodbye、wave | 前臂左右摆动 |
| 坐 / 站 sit / stand | sit down、stand up | 关节角度切换 |
| 惊讶 / 想 / 欢呼 / 举卡 / 翻书 | 讲解员表情动作（V6） | 同上骨架 + 表情 |

**扩展规则**：新动作 = 新增一组姿态 + 时间序列，加进同一个动作库（通用引擎工具，暂定 `k.act(演员, 动作, 开始, 时长, {to, prop})`），在 `HANDOFF.md` 登记；不在单个案例文件里各写一套。

**现状（db13720）**：port 幕的搬运、进港、过关卡是用「货箱 / 卷轴 / 船自己移动」和火柴人平移来表现的，**人没有做搬、拿、放的动作**，按 R4 需要补：im-/ex-port 要有搬运工抱箱子走进 / 走出、passport 的旅客要走路过关、support 要有小人从下面托住。列入阶段 1。
