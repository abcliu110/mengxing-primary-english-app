## 0. 四条硬规则（任何一条不满足 = 不通过）

| # | 规则 |
|---|---|
| R1 | 新内容和旧内容重复：删旧的，把旧内容并进新模块（步骤见 §10） |
| R2 | **画面上出现的每一个英文单词都要有例句；单词和句子都必须有语音朗读**，不能只有文字（§7） |
| R3 | 讲错的直接改；故意简化的保留并标 💡 / ✂️ / ⚠️；每个 📜 都有出处（§11） |
| R4 | **单词或例句里有动作（动词、短语动词），必须由讲解员小人或场景角色演出来**，和朗读同步（§8） |

## 1. 风格基线（视觉标准详见 §9）

| 项目 | 规范 |
|---|---|
| 画布 | 960×600：0–544 白板（米白底 + 30px 浅格子），544–600 讲解字幕条；有朗读时下面加 600–650 🔊 朗读条 |
| 画线 | 一笔一笔画出来（`stroke-dashoffset`），带轻微手抖；描完边再淡入涂色 |
| 写字 | 从左往右「写」出来，拿马克笔的手跟着笔尖走；不在写的时候，手退到右下角 |
| 字体 | 中文默认 ZH 字体；英文单词、音标、句子用等宽 `MONO`（`k.mono()` 依赖等宽，每字宽 0.6×字号） |
| 版面 | 标题行 y≈52；内容区 y 80–530；**不要画到 y>535**，不要出左右边界（x 12–948） |
| 结尾 | 定格在一张能截图复习的总结图 / 收尾金句卡上，字幕给口诀 |
| 时长 | 实验室 40–60 秒；第一性原理 35–55 秒；单词身世每幕 ≤ 90 秒画面 + 朗读时间（朗读时画面停住，总长可超出） |

## 2. 讲解与术语

1. **每画一步，字幕换一句**：`N("术语：", "大白话解释")`。一句不超过约 48 个汉字；字幕至少停留约 2 秒。
2. **页面上和动画里出现的难懂术语都要解释**：动画里第一次出现时用字幕解释；页面上用案例的 `terms` 数组自动生成「📖 术语小词典」（第 1 个案例放基础词条，其他案例只放新词条）。同一个术语全 App 用同一种说法。
3. 页面原有的比喻（门派、护卫、照妖镜……）要在动画里用一句话说清楚它指什么。
4. **每幕只引入一个新概念**，结构「问题 → 原理 / 场景 → 示范 → 结论 / 口诀」。

## 3. 内容规则

- **数据一致**：动画里的单词、例句、规则和主文件数据一致（导出见 `lab_data.json`）。数据错了直接改主文件（§6），记进 HANDOFF。
- 数据项条目很多时，挑 3–4 个画完整过程，其余在最后一屏快速列出（列出的英文词同样要满足 R2）。
- 例句只用**正确的英文**、课标词短句（4–9 词）；超出课标的词标 🥚 彩蛋词（课标词以词库 `VOCAB_DB` 为准）。
- 单词身世类：每幕走完四层（是什么 / 为什么 / 怎么推 / 我会用），有一句话洞见和 🔮 预测题（`word_origins/DEPTH_AND_ANIMATION.md`）。

## 4. 标准流程：做一幕 / 一个模块

```
① 出处核实 → ② 分镜（英文词清单 + 动作词清单）→ ③ 白板动画 → ④ 朗读 → ⑤ 验收脚本 → ⑥ 截图逐张看 → ⑦ 提交 + 更新文档
```

### ① 出处核实（先于一切）
- 凡要标 📜 的说法（词源、历史、神话、数据），先查 etymonline / Oxford / 维基百科（看它引用的原始出处）/ 原始论文；**打开页面读原文**，不能只看搜索摘要。
- 写进对应目录的 `SOURCES.md`（规则见 §11）。查不到出处的，不能标 📜，只能标 💡 / ❓ / ⚠️，或者不讲。
- 有多种说法的（如 Europe 名字来源）标 ❓，并列写出，不写成定论。

### ② 分镜
1. 读页面原文和数据数组；单词身世类读 DESIGN + DEPTH 文档的镜头表。
2. 每幕 5–8 步（单词身世：5 步溯源幕 + 🔮 预测），列出要解释的术语。
3. **列「英文词清单」**：这一幕画面上会出现的所有英文单词（含专有名词、词块）→ 每个配一句例句（或词块配「单独朗读」），见 §7。
4. **列「动作词清单」**：每句例句、每个单词里的动作（carry、run、take off、port 的「搬运」……）→ 每个配一个动作（演员 + 动作库里的动作 + 道具），见 §8。动作库里没有的，先登记成新动作。
5. 分镜写在模块的 DESIGN / STORYBOARD 文档里（表格：镜头 | 画面动作 | 字幕 | 朗读句 | 演员动作 | 深度层）。

### ③ 白板动画（先出带时间码的分镜和低保真样片确认节奏，再按商业动画标准 M1–M12 精修，见 MASTER_DESIGN §2.7）
- 新建 `docs/whiteboard/src/cases/<id>.js`：
  ```js
  WB_LAB.<id> = [ { build(k) { const { C, N } = k; N("", "开场白"); k.header("副标题", "大标题", false); ... }, terms: [["术语", "解释"], ...] } ];
  ```
- 时间按调用顺序自动排（`k.go(秒)` 返回开始时间并推进游标），停顿 `k.wait(秒)`；同时画用 `k.go(时长, 0)`。
- 工具：底层 `P / T / F / N`；手绘形状 `wl / roughRect / ellipse / wave / cloud / rectD`；组件 `header / head / zh / circle / bracket / note / mono / squiggle / underline / strike / caret / above / redX / chip / arrow / final …`；动效 `group / move / arc / path / buzz / fade / rot / hide / camera`；徽章与彩蛋 `badges / badge / egg`；朗读 `say`。
- 系列道具：第一性原理 `cases/fp_props.js`；单词身世 `cases/wo_props.js`（`scene / step / shot / wipe / map / boat / wind / stamp / morph / snap / hold / finish …`）。
- 新图形先写在案例文件里；**确实通用的**加进引擎或道具文件，并在 `CHANGELOG.md` §5「引擎通用新工具」登记。改引擎后必须回归旧案例。

### ④ 朗读（§7）
- 每个英文词：先 `word` 单独读，再读例句；读的时候画面停住；只读正确英文。

### ⑤ 验收脚本
- 写进主文件：`python3 docs/whiteboard/src/insert_wb.py`（登记列表：实验室 `READY`、第一性原理 `FP_READY`、单词身世 `WO_READY`）。登记的模块写成按需加载的 `<script type="text/plain" id="wbmod-<id>">`，第一次进入时才执行（决策 13）；案例文件里不能出现 `</script` 和 `<!--`（脚本会报错拦下）。
- 脚本：
  - `node --check`：`python3 docs/whiteboard/src/jscheck.py`（抽出主文件全部直接执行的 `<script>` + 按需加载模块 `wbmod-*`，拼起来检查并逐个检查；末尾自动跑 `anchorcheck.py`，核对补丁锚点 / 插入标记没有静默丢失）；
  - 实验室 `appwb.py <页签> <目录>`；第一性原理 `appfp.py <0-5> <目录>`；单词身世 `appwo.py <目录>`：每幕 `mounted: True`、`bad: None`、`errors: []`、无 NaN / undefined；
  - 回归：`appwb.py bamboo_tree`、`appfp.py 0`、`appwo.py` 都要过；
  - **朗读覆盖检查（R2）**：`python3 docs/whiteboard/src/r2check.py <幕 id> [--all-items] [--strict]`（先 `insert_wb.py`）：抽出画面上全部英文词 / 词块 / 句子，对照 `say` 登记，报「缺单独朗读 / 缺例句 / 句子缺朗读」；
  - **动作覆盖检查（R4）**：同一个脚本；案例写 `actionWords: [{ word, act }]`，逐个对照 `k.act(…, { words })` / `k.actFx(words, …)` 登记，并检查动作和含该词的朗读时间重叠；
  - **引擎回归**：改引擎后，旧幕在新旧引擎下渲染结果要逐字节一致：`reg_render.py 旧.html old.json` → `reg_render.py 新.html new.json` → `reg_render.py --diff old.json new.json`（diff=0 才算过；旧版本用 `git show HEAD:萌星小学英语_最终合并版.html > 旧.html` 取）；
  - **首屏耗时**（按需加载，决策 13）：`measure_load.py 旧.html 新.html --n 12`，首页可交互（ready）不能变差；
  - **商业动画指标**：`measure_sync.py`（朗读同步误差 ≤0.2 秒）、`measure_fps.py`（fps，和升级前对比不能变差）、`measure_seek.py`（拖动 / 重播三种路径状态一致）；

### ⑥ 截图逐张看
- `python3 docs/whiteboard/src/preview_shots.py <id> <目录> 18s,35s,…,1.0`（可写秒数或比例）：**每个镜头结束前、关键动作中间、最后一帧**各截一张。
- 用看图工具真正打开每张图：重叠、出界、文字压线、字幕太长、手挡住正在讲的内容、小人挡住内容、颜色超出调色板。
- 预览动画：`preview.html?tab=<id>&case=0`。

### ⑦ 提交 + 更新文档
- 做完一幕 / 一个页签就提交一次，**直接推 `master`，不新建分支**；提交说明写清做了什么、改了哪些数据、验收结果。
- 在 `CHANGELOG.md` 记进度流水、更新 `HANDOFF.md` 现状；单词身世类在 `DESIGN_HANDOFF.md` 附「四层 × 四关 + 听读关 + 动作关」自查表。

## 6. 发现 bug 立即修
做动画时发现页面数据或代码有错，**直接改主文件里的数据和 cases 脚本**，两边一致，提交说明写清改了什么，在 HANDOFF 打 ✔，不需要再问用户。讲法问题（简化、联想）不删，标徽章。

## 7. 英文朗读（R2，决策 17）

**规则**
1. **画面上出现的每一个完整英文单词（含专有名词，如 Rome、Europe），都要「单独读词 + 读一句例句」**；前缀、词根、拉丁 / 希腊原词（im-、port 词块、medi、terra、portus）至少单独读一遍。
2. 在「正确的英文出现」或「词拼合成功」的那一刻读；**读的时候画面停住**，读完再走。
3. 只读正确的英文；中式英语、病句、被划掉的词不读。
4. 读到哪个词，朗读条上哪个词高亮，白板上同一个词也同步高亮（V5）；中文只显示字幕，不读出来。
5. 例句用课标词短句，贴合画面；超出课标的词在朗读条上显示 🥚（`say(…, { egg: [...] })`）。
6. 设备没有英文语音时不停顿，只显示文字，不能卡住。

**写法**
```js
k.say("The ship sails into the port.", { zh: "船驶进港口。", word: "port" });
k.say("This is a good opportunity.", { zh: "这是一个好机会。", word: "opportunity", egg: ["opportunity"] });
// k.final(text, crown, zhLine) 会自动朗读 text；不读用 { noSay: true }
```
- 一句话里可以覆盖多个词（例句里出现的词算「有例句」），但每个词仍要单独读一遍（`word` 可以写多个词，用空格分开）。

## 8. 讲解员小人与人物动作（决策 16、19；R4）

**形象**：和白板同风格的简笔线条小人（墨黑线条、线宽约 2.5、圆头、点点眼睛、弧线嘴，可戴一顶小帽子做标识）。**形象先出设计稿给用户确认，确认前不进动画。**

**使用规范**
1. **位置**：默认站在白板左下或右下角（不超过约 120×150 px 的区域），**不挡内容、不压字幕、不和拿笔的手抢同一个角**；需要演动作时可以走进场景，演完回到角落。
2. **什么时候出场**：开场打招呼（挥手）→ 讲解时指着正在讲的东西 → 预测题时「想」→ 揭晓时「欢呼」；不讲的时候站着不动，不做装饰性小动作（动作即语义）。
3. **朗读时口型**：读句子时嘴巴开合跟着朗读节奏，读完闭嘴。
4. **演动作（R4）**：分镜里每个动作词都要分配「演员（小人或场景角色）+ 动作 + 道具 + 和哪句朗读同步」。动作用动作库（`MASTER_DESIGN.md` §2.6：走、跑、搬、拿、放、指、举、跳、转身、挥手……），读到这个词时动作正在发生；库里没有的动作先登记再用，不在案例文件里各写一套。
5. 场景角色（搬运工、旅客、公主……）和小人共用同一套骨架和动作库，只换帽子、衣服、道具。

## 9. 视觉标准（商业级白板，决策 18）

> 全部保持**离线单文件、双击即用**：不引外部字体、图片、音频文件或库。

| # | 标准 | 做法 | 验收检查 |
|---|---|---|---|
| V1 | 手拿马克笔，跟着笔尖画 | 画线、写字时笔尖贴着当前笔画；动效时手退到右下角；换笔画时平滑移过去 | [ ] 截图里手的位置在笔尖上；镜头缩放时也对；没有瞬移 |
| V2 | 笔触有粗细和起收笔；重点词荧光笔底色 | 线条中段略粗、两端略细；重点词先刷半透明荧光底色再写 | [ ] 线条不是均匀粗细；每幕的关键词有荧光底色（每屏不超过 3 处） |
| V3 | 统一调色板、字号层级、留白网格 | 墨黑 `#1f2937` + 红 `#e11d48`（错误 / 术语）+ 绿 `#059669`（正确 / 结论）+ 蓝 `#2563eb`（主角词 / 词根）；灰只用于注释，荧光黄 / 绿只作底色。字号：标题 32 · 小标题 22 · 正文 18–20 · 注释 13–15。12 列网格，四周留白 ≥ 24 px | [ ] 没有调色板以外的颜色；字号只用这 4 级；元素对齐网格、不挤 |
| V4 | 分类缓动、错开出场、镜头不硬切 | 出现 = 弹入轻微过冲；吸附 = 回弹；移动 = 缓入缓出；退场 = 快出；同组元素错开 0.08–0.15 秒；镜头只推拉平移 | [ ] 拖进度条逐帧看：没有画面瞬间跳变；同组元素不是同时冒出来 |
| V5 | 画面与朗读对齐 | 读到哪个词，朗读条和白板上的同一个词都高亮；读时画面停住 | [ ] 每句朗读时白板上对应词高亮；读完才进入下一步 |
| V6 | 讲解员小人多姿态 + 口型 | 指、惊讶、举卡、翻书（另有想、欢呼）；朗读时口型开合 | [ ] 小人姿态和讲解内容一致；朗读时嘴在动；不挡内容 |
| V7 | 音效 | 马克笔沙沙、弹出、答对「叮」；Web Audio 现场合成，几 KB 以内；控制条一键静音（和朗读开关分开）；朗读时音效自动压低 | [ ] 静音键有效；音效不盖过朗读；文件体积增加 < 10 KB |
| V8 | 擦除式转场 + 统一片头和收尾金句卡 | 镜头之间用板擦擦掉；每幕片头（标题 + 徽章 + 进度条）和收尾金句卡（一句话洞见 + 口诀）统一样式 | [ ] 镜头切换有擦除动画；片头、收尾卡样式和其他幕一致 |

**引擎 v2 用法（2026-10-29，port 样板幕）**：案例 build 第一行 `k.v2()` 打开视觉标准 + 商业动画标准（旧幕不调用就完全不变）。常用：`k.titleCard / k.quoteCard`（统一片头 / 收尾金句卡）、`k.hlText`（荧光底色，每屏 ≤3 处）、`k.pop / k.squash`（弹入、落地挤压）、`D.wipe()`（v2 下自动是板擦擦除）、`k.actor / k.act / k.prop / k.expr / k.look`（讲解员小人和场景角色，见 `src/wb_actor.js` 文件头）；颜色用 `k.PAL`，字号用 `k.FS`。角色服装色是 V3 调色板的唯一例外；可信度徽章、🥚 保持全 App 统一色。样板：`cases/wo_port.js`，分镜：`word_origins/PORT_STORYBOARD_V2.md`。

**升级顺序**：先只用 port 一幕做 V1–V8 升级，出「升级前 / 升级后」对比截图给用户看，满意再铺开（`MASTER_DESIGN.md` §4 阶段 1）。旧幕在升级前沿用旧配色，不算违规。

## 10. 合并旧页签（R1）的步骤

6. 提交说明写「合并：旧 X → 新 Y，删除了 …」；更新 `MASTER_DESIGN.md` §3 总表状态和 HANDOFF。

## 11. 出处记录规则

1. 每个模块目录一个 `SOURCES.md`（如 `word_origins/SOURCES.md`）；按幕分节，表格列：**序号 | 动画里的说法 | 徽章 | 出处原文要点（英文原句摘一句）| 网址**；文件头写核对日期。
2. 优先级：etymonline、Oxford（OED / Lexico）→ 维基百科（看它引用的原始出处）→ 学术论文 / 原始数据；不用无出处的公众号、短视频。
3. **必须打开页面读原文**；搜索摘要不算出处。网页抓不到时换另一个可靠来源，并在表里注明。
4. 有多种说法的，表里全部列出并标 ❓；动画里也说「有多种说法」。
5. 中文对照（如「进口、出口的口」）不是词源，标「对照，不是同源」，不标 📜。
6. 词卡 📖 身世标签只给 SOURCES.md 里有出处行的词。

## 12. 常见坑
- 涂色 `F()` 紧跟它对应的描边 `P()`；一个形状两笔描边用 `back: 2`。
- 工具调用顺序 = 画的顺序；同时画用 `k.go(时长, 0)`。
- `k.zh()` 按「每字 = 字号」排版，中英混排不要用它圈字。
- 音标字符（ʊ ə ː θ ˈ）宽度不准，圈音标时留余量。
- `estW` 对中英混排估得偏宽，egg / 徽章跟在文字后面时要看截图微调。
- 引擎 `mount` 时测文字宽度，SVG 必须已经在页面里。
- `camera` 回到 z=1 时中心必须是 480,272。
- 单词身世：`D.back()` 每次开新静态组，后画的在上层；`D.finish(f)` 放在 build 最后。
- 环境：沙箱重置后重装 Playwright（`pip install playwright && python3 -m playwright install chromium && python3 -m playwright install-deps chromium`），并装 `fonts-noto-color-emoji`、`fonts-wqy-zenhei`，否则截图里 emoji 和中文是方块。

## 14. 老动画 / HD 剧场白板化的标准流程（决策 23 / 24）

适用：老白板案例（旧引擎、无讲解员）和三大厅 HD canvas 剧场（`hdTheaterState` 系列、CSS keyframes 小动画）。目标样板：port v2。

1. **导出旧内容清单（R1，先于一切）**：
   - 老白板：升级前把原文件存为 `cases/<id>_classic.js`；
   - HD 剧场：把该入口的全部旧文字、例句、小测、提示语、按钮文案导出成 `<模块>/INVENTORY_<入口>.md`（来源：数据库字段 + canvas 代码里的字符串），逐条编号。
2. **动作清点（R4）**：列出朗读和字幕里所有描述动作的词（动词、短语动词、「搬运」「转身」这类中文动作描述），每个都要对应一个 `k.act` 动作；动作库没有的，先在 `wb_actor.js` 加（只加不改，加完跑全量渲染回归确认旧幕不变）。
3. **数据驱动的做模板**：单词卡、框架语义、语法点、口语场景等同构内容，写一个白板模板 + 「动词 → 动作」映射表，按数据生成幕，不逐个手写；模板里要有讲解员、片头、板擦转场、金句卡。
4. **做幕**：引擎 v2（`k.v2()`）+ 讲解员 + V3 四色 + R2（每个英文词单读 + 例句）+ R4 `actionWords`，动作与朗读同步（动作起点挂在对应 `say` 的单词时刻上）。
5. **试点 → 用户审片 → 批量**：每类先做一个试点，出升级前后同一句朗读时刻的对比图给用户；**用户认可前不得批量**。
6. **拆旧**：白板版验收通过、清单 ❌0 后，才删旧 canvas 代码 / 旧入口改跳转；删除单独一个提交，提交说明写清单文件名。
7. **提交**：一个文件 / 一个入口一个提交，直接推 `master`；CHANGELOG 记一行。

## 15. 词源 / 格林定律 / 词根词缀入库流程（决策 25）

1. **审计**：从 `VOCAB_DB` 导出全部词；逐词查 Wiktionary（词源段的 `inh/der/bor/cog/affix/suffix/prefix/compound` 模板）和 Etymonline，生成候选表；报告写进 `word_origins/COVERAGE.md`（之前 / 之后、各类条数、未入库原因）。
2. **判定**（MASTER_DESIGN 决策 25）：词源 = 有可核对出处；格林定律 = 本族词与拉丁 / 希腊同源词有文献支持的辅音对应；词根词缀 = 可拆成有意义的部分且有出处。**难度不影响入库**，只影响展示层（课标词优先展示、超纲标 🥚）。
3. **出处**：每条至少一个网址（Etymonline 词条 / Wiktionary 词条 / 维基「Grimm's law」表），记在数据里和 `word_origins/SOURCES.md`；拿不准标 ❓ 或不入库，写原因，**绝不编造**。
4. **旧字段**：`etymology`（巧记小故事）、`affix_root` 原样保留；发现错误说法加 R3 纠正标注（⚠️ + 正确说法 + 出处），不删。
5. **R2**：每个入库词和同源词展示时都要单读 + 例句朗读（拉丁 / 希腊词只单读）。
6. **展示**：数据（`ETYM_DB` / `GRIMM_DB` / `MORPH_DB`）与展示分离；格林定律按规则组，每组一个白板模板幕 + 配对轮播；词卡 📖 身世标签由数据自动生成。
7. **分批提交**：格林定律按规则组、词源按年级、词根词缀按词缀族，每批一个提交并更新 COVERAGE.md。
