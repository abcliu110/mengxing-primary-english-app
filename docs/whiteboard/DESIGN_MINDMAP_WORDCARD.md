## 1. 主题思维导图

### 1.1 现状
- 入口：单词大世界 → 主题大世界 → 子主题 → 「🗺️ 主题思维导图视图」。
- `initThemeMindMapCanvas(sub, words, colloc, allSubIds)`：中心节点 `🌍 子主题`，环绕最多 18 个单词节点（emoji + 单词 + 中文前 8 字），两侧「🔗 常用搭配动词」「✨ 评价形容词」各 3 条；点节点开词卡并朗读，滚轮/按钮缩放、拖拽平移。
- 25 个子主题，词数 14–171 不等（导图只取前 18 个）。

### 1.2 为什么不把交互导图本身换成白板
白板动画是「看」的，导图是「点」的：孩子靠它跳进单词卡。换成播放型白板会丢掉点词开卡、缩放、拖拽三项功能，违背 R1（功能只增不减）。所以导图保留，白板负责「讲」。

### 1.3 新增：导图讲解幕（每个子主题 1 幕）
位置：导图卡片上方，与其他厅相同的 v5 iframe 舞台；下方原交互导图不动。

画法（新增 auto.js 的「mindmap」版式，其余沿用 v5.1）：
1. 开场：白板中央手写圆圈 + `🌍 子主题名`，讲解员小人入场（帧组见 1.5）。
2. 分支：从中心手绘 4–6 条粗枝，每条枝 = 一个**语义小组**（见 1.4），枝头写组名。
3. 叶子：每组 2–4 个代表词逐个「写上去」——emoji + 单词 + 中文；写一个读一个（英文 → 中文），沿用统一阅读节奏。
4. 搭配：左右两个手绘框写出「常用搭配动词」「评价形容词」各 3 条，并各配一句朗读示例（取 `collocations` 原文）。
5. 收束：镜头拉远看到整张导图，字幕「点下面导图里的任意单词，打开词卡继续学」。
- 时长目标 60–90 秒；一幕不超过 18 个叶子（与现有导图一致），其余词靠下方交互导图。

### 1.4 语义小组从哪里来（不编造）
- 首选：数据已有字段（`pos` 词性、`theme_sub` 内的 `senses[0].scene`、`sight_type`）按规则分组，例如「学校与学习」→ 文具 / 场所 / 动作 / 科目，由词性 + 词义关键词规则归类。
- 规则分不出的词放「更多」组，不硬凑。
- 分组表落盘为 `docs/whiteboard/v5/mindmap_groups.json`（每个子主题：组名 → 词 id 列表），**逐条人工过目**后才生成；组名只用中文常用词，不引入数据里没有的知识点。

### 1.5 人物与帧
固定一组「指点 / 思考 / 讲解」帧（`l_point`、`l_think`、`l_speak`、`l_idea0`），25 幕共用一个帧库，共享块只存一份。

### 1.6 R1 清单与验收
- 清单生成器 `src/gen_mindmap_inventory.py`：从 VOCAB_DB 导出旧导图上全部文字（中心名、18 个节点的 emoji+单词+中文**完整**词义、两框标题与 6 条搭配、提示语），新幕只增不减。
- 每幕：R1 缺 0、`deterministic True`、`errors none`、`sandbox none`；App 回归：讲解幕已换 v5、下方导图仍可点开词卡、缩放/拖拽正常、0 报错。

## 2. 普通单词卡：通用白板模板

### 2.1 现状
- 非多义词的词卡正面：`startWordModalCanvasAnim(w, polyAct)` 走「三维深度解剖」三幕（`hdTheaterState.actIdx` 切换）：
  - ① 词源与音节拆解：`syllables` + `memory_tip` + `etymology`
  - ② 积木构词与搭配：`affix_root` 前半 + `collocations.verbs`
  - ③ 汉英句法防坑：`syntax_contrast`
- 顶部横幅：`emoji word phonetic —【pos】meaning` + `affix_root`/`memory_tip`；左右两个角色；字幕条读例句。
- 旧画法用 `slice()` 截断长句（如 `etymology.slice(0,44)`），孩子看不到完整内容。

### 2.2 为什么不每词预生成
约 1470 词 × 3 幕 ≈ 4400 幕；按已上线各幕平均体积估算主文件将增加十几到二十多 MB（现 15.5 MB），首屏和手机都吃不消，且每改一次数据要重新生成全部。

### 2.3 方案：一个模板，现场排版
- 引擎、字体、auto.js 版面引擎已是**全 App 共享块**（`wb5blob-*`）；字体子集 `font_chars.txt` 已覆盖 VOCAB_DB 全部字符（核对：缺 0 字）。
- 新增**一个**模板幕 `wordcard_tpl`：内容是「读取父页面传入的词数据 → 生成 ITEMS → `autoBuild`」，与预生成幕用的是同一套排版与节奏代码，画面风格完全一致。
- 挂载：`startWordModalCanvasAnim` 开头加挂钩（与其他厅相同的 `WB5_HD` 方式）：非多义、非功能词 → 用模板 iframe，`postMessage` 传 `{word, act}`；多义词仍走已生成的 `hd_poly_*`；功能词不变。
- 三幕保留（页面已有三幕按钮），每幕内容：
  - **幕 1 词源与音节**：横幅（完整）、音节拆解、记忆口诀、词源小故事（**完整原文**）、读例句 `example_en ｜ example_zh`。
  - **幕 2 积木构词与搭配**：`affix_root`（完整，含家族串记）、搭配动词与形容词、读第一条搭配。
  - **幕 3 句法防坑**：`syntax_contrast` 完整原文、`spelling_alert`（有则写）、读 `senses[0].ex_en ｜ ex_zh`。
- 人物：固定帧组（`l_think`、`l_point`、`l_books`、`l_speak`）；按 `theme_macro` 只换讲解员动作顺序，不新增帧。
- 字段缺失时该行跳过，不补写、不编造。

### 2.4 确定性与验收（不逐词存档，但逐词验）
- 模板排版是纯函数：同一词同一幕，任何设备结果相同（与预生成幕同一 `deterministic` 检查）。
- 批量离线验收脚本 `v5/check_wordcard_tpl.py`：无头浏览器把 1470 词 × 3 幕全部跑一遍，逐幕记录：R1（对照旧舞台文字的完整原句，缺 0）、时长、`errors none`、文字是否溢出版面。结果写 `lab/WORDCARD_TPL_REPORT.md`（只记汇总 + 不合格清单，不存每词截图）。
- 不合格的词（如某字段超长导致一板放不下）由版面引擎自动换板；仍不行的列入报告人工处理。
- App 回归：随机 30 词 + 全部 25 子主题首词，开卡、切三幕、翻卡、上下一张、关闭，0 报错，旧 canvas 不再出现。

### 2.5 风险
- **首帧延迟**：现场排版比读预生成幕多一次版面计算（预计 <100 ms），需在中低端手机实测；超标则对高频前 300 词预生成，其余现场排版。
- **离线**：全部资源在主文件内，无网络依赖，与现状一致。
- **字体新字**：日后数据新增生僻字，需重跑 `gen_font_chars.py`；验收脚本会把缺字列为不合格。
