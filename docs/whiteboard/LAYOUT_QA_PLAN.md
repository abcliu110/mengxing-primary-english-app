# 白板动画布局质量保障技术方案

> 起因：`fp_boundedness_1_v2` 第一版交付后被指出「动画的逻辑不对，各种元素的位置不对，包括文字可能被覆盖」。复盘确认问题属实，且全部是**流程问题、不是灵感问题**：场景是按坐标心算写出来的，从未真正渲染过一帧。本文档把这次踩过的坑固化成规范与工具，保证以后每一幕在交付前都过同一套关。
>
> 适用范围：`docs/whiteboard/v5` 全部场景（wb5 引擎 + concept 组件 + cast 素材库）。

---

## 1. 事故复盘：第一版到底错在哪

在真实浏览器里逐帧截图后，第一版共查出 11 处问题，归为四类根因：

| # | 具体问题 | 根因类别 |
|---|---|---|
| 1 | `l_stand` 帧其实是「坐在椅子上」，主角多处凭空坐着 | A 素材语义未核实 |
| 2 | `l_read` 帧自带一整张课桌，压住舞台桌与流体 | A 素材语义未核实 |
| 3 | FI 归一化的 ref 帧选了坐姿帧，全员比例被带偏 | A 素材语义未核实 |
| 4 | 茶壶压在主角头上（壶的落点与演员包围盒相交） | B 没有空间规范 |
| 5 | 咖啡馆招牌（墙面）与两行字幕条、预测倒计时圆环同高相撞 | B 没有空间规范 |
| 6 | 苹果的「2」徽章正好盖在红色结论字上 | B 没有空间规范 |
| 7 | `rices ?` 块与底部朗读词块同一行交叠 | B 没有空间规范 |
| 8 | 「有边✓/没边✗」结论块贴在地板带上，被朗读词块二次覆盖 | B 没有空间规范 |
| 9 | bread 出现三个互相重叠的标签（站位标签 + 两块分片标签） | B 没有空间规范 |
| 10 | 两只咖啡杯在切苹果时仍留在画面，苹果/面包叠进杯子的框里（上一拍的展品不退场） | C 动画逻辑无检查 |
| 11 | 流体波浪横贯整个舞台、穿过演员身体（`schemaContainer` 的 `spread` 默认 1.5 没人管） | C 动画逻辑无检查 |
| — | 以上全部：第一版交付前只用 Node 桩跑过逻辑冒烟，**没有任何一帧被真正渲染、被眼睛看过**；项目自带的 `insightcheck` 因环境缺浏览器根本没跑成 | D 没有视觉验证回路 |

结论：靠「写的时候小心」防不住这类问题。四类根因要分别用**清单、规范、自动检测、门禁**堵死。

## 2. 方案总览

每一幕的交付流水线固定为六步，任何一步不过就不交付：

```
写场景 → ①构建 → ②insightcheck 官方检查（必须 0 不合格）
       → ③自动截图（固定时刻表） → ④重叠自动检测 → ⑤人工抽查签核 → 交付
```

支撑这条流水线的四项基础设施：

1. **素材语义清单**（堵 A）：cast 每一帧长什么样，先看图登记，再允许引用。
2. **舞台分区规范**（堵 B）：1920×1080 的每个区域归谁，先查表再落坐标。
3. **截图 + 重叠检测工具**（堵 C、D）：无头浏览器逐帧出图，文字与元素的包围盒自动查撞。
4. **环境固化与引擎怪癖清单**（堵 D 及复发）：检查器一键可跑；引擎的坑写成活文档，写场景前必读。

## 3. 子方案一：素材语义清单（选角表）

**问题本质**：文件名不可信。`l_stand` 不是站立、`l_read` 自带课桌、`l_coff*` 里混着穿外套的帧——只看名字选角必然翻车。

**措施**：

1. 新增脚本 `v5/tools/cast_sheet.py`：把 `sprites/cast/*.webp` 拼成一张带文件名标注的联系表（contact sheet），一张图看全所有帧。
2. 新增登记文件 `v5/sprites/CAST.md`，每帧一行，人工看图填写：

   | 帧 | 内容（看图说话） | 姿态 | 自带道具/文字 | 可用性 |
   |---|---|---|---|---|
   | l_stand | 坐在椅子上侧身 | 坐姿 | 椅子 | ⚠️ 禁用作站立/基准帧 |
   | l_read | 坐在课桌后读书 | 坐姿 | 课桌+书 | ⚠️ 仅限「教室桌前」场景 |
   | l_coff0 | 站立、穿橙色外套、微笑 | 站立 | 无 | ✅ 中性站立，**定为全剧基准帧（ref）** |
   | l_think | 站立思考，自带思考气泡 | 站立 | 气泡（图内） | ✅ 注意气泡会占左上空间 |
   | l_idea0 | 站立拿书挠头，自带「?」 | 站立 | 书+问号 | ✅ 疑惑专用 |
   | l_point | 站立指点、惊讶 | 站立 | 背包 | ✅ |
   | l_laugh | 站立大笑竖拇指 | 站立 | 无 | ✅ |
   | l_w0–3 | 提购物袋行走 | 行走 | 购物袋 | ✅ walk 专用 |
   | woman | 站立微笑 | 站立 | 无 | ✅ |

3. **规则**（写进场景评审清单）：
   - 场景里出现的每一帧，必须能在 CAST.md 里查到且标记为可用；
   - 新增/更换素材后，先重跑联系表、更新 CAST.md，再写场景；
   - 所有 actor 的 `ref` 只能用 CAST.md 标定的基准帧（当前为 `l_coff0`），保证比例归一化不被坐姿/带家具帧带偏。

## 4. 子方案二：舞台分区规范（坐标宪法）

**问题本质**：元素落位全凭随手。字幕、招牌、圆环、词块各占哪一行，没有约定，必然相撞。

**措施**：把 1920×1080 分成固定功能区（纵坐标），写场景时先查表：

| 区域 | y 范围 | 归属 | 规则 |
|---|---|---|---|
| 字幕区 | 22 – 136 | narr 旁白条（可两行） | **任何装饰/招牌/道具禁止进入**；预测圆环（1693,208）与本区右段同高，右上 1450–1920 禁放横向长条 |
| 提问区 | 150 – 330 | 冲突问题块、预测问题块（如 `rices ?`）、结论块（有边✓/没边✗） | 全幕视觉焦点带；演员头部（约 300–560）在此带左侧，中心展品的问题块放 x≈960 |
| 展品区 | 330 – 790 | 主展品（容器/图/徽章） | 同一时刻只许**一组**主展品在场（见子方案三·退场规则）；标签贴展品下缘，不另开行 |
| 桌面线 | 796 – 822 | 舞台桌 | 「坐在桌上」的展品底边必须落在 770–800；家具文字（如店名）只许写在桌面正面 |
| 地板区 | 838 – 1080 | 朗读词块（say 条 y≈803 起）+ morphLetters（y≈905） | **结论块、徽章、展品一律禁止进入**——这里是朗读条的领地（事故 7、8 的根源） |
| 演员区 | x 120 – 560 | 主角（宽约 300–420） | 展品左缘 ≥ 580；流体/波浪的横向范围不得进入 x<560（事故 11 的根源） |
| 角标区 | 左下 / 右下 | 章节角标、幕标题（引擎自带） | 禁放任何场景元素 |

配套硬规则：

- **同行查重**：新元素落位前，先列出与它 y 区间相交的全部已有元素（含 until 已过期的），逐一确认 x 不交叠或有意分层；
- **文字三不压**：文字不压文字、文字不压人物面部/身体、文字不压家具线条（桌面、地板分界）；
- **家具文字只许一个位置**：店名/招牌写在家具本体上（如桌子正面），永不上墙——墙面与字幕区天然冲突。

本幕修正后验证过的坐标样板（可直接复用）：结论块 (680/1360, 262)、问题块 (960, 262)、展品中心 (960, 520)、杯子中心 y=630（底边贴桌面）、流体容器 (850, 640, w320, spread=1.0)。

## 5. 子方案三：动画逻辑规则（退场与范围）

针对事故 10、11 这类「逻辑不对」，把三条规则写进场景评审清单：

1. **退场规则**：上一拍的展品在下一组展品入场前必须退场（`until` 对齐拍界）。「结果帧留场陪讲」只允许不占展品区的元素（如底部 morph 结论文字），且必须复核与下一组展品的包围盒不交。
2. **范围规则**：`schemaContainer` 必须显式给 `spread`，并验算波浪横向范围 `x ± w×spread` 不进演员区、不出画面；`unbounded` 不是「铺满全场」。
3. **因果贴合**：动作元素必须落在语义位置——倒流线终点必须落在液体表面±20px 内、徽章 drop 点必须落在目标物上缘、数字滑落终点不高于桌面。写完在截图里逐项核对（见子方案四的时刻表）。

## 6. 子方案四：自动截图 + 重叠检测（视觉验证回路）

**问题本质**：事故的共同点是「没人看过画面」。把「看」变成流水线的固定动作，且尽量自动化。

### 6.1 固定时刻表截图（立即可用，已有原型）

- 工具 `v5/tools/shots.py`（原型已在本幕验证）：无头 Chromium 打开构建产物，用播放器 `__seek(t)` 跳到时刻表逐帧截 `#stage`。
- 时刻表生成规则：每个 step 至少 3 帧（入场后、核心动作中、宣判/揭晓时），外加每次 drop/swap/predict/切分动作的命中帧；一幕约 20 帧。
- 截图存 `shots/<幕名>/`，与场景文件同批交付/提交，作为评审材料；交付说明里必须写明「已逐帧看过」并列出看过的帧数。

### 6.2 重叠自动检测（把人眼检查变成机器预检）

在截图同一步里注入检测脚本，自动报告三类相撞（输出帧号 + 元素对 + 交叠面积）：

- **文字-文字**：拦截 `CanvasRenderingContext2D.fillText` 记录每帧文字包围盒（引擎所有文字都经 fillText），两两求交，交叠 > 文字面积 10% 报警；
- **文字-演员**：actor 的当前包围盒（帧图包围盒按 actor x/ground/h 换算）与文字包围盒求交，面部区（上 35%）交叠即报警；
- **元素-元素**：chip/pic/container 的注册表（concept 组件内部已有 items 列表，可扩展导出调试接口 `__WB5_DEBUG_BOXES__`）两两求交，排除白名单（如徽章贴容器角、drop 命中帧）。

报警不自动判死刑，但**必须逐条人工确认并在交付说明里销项**——和静态字指标同理：机器负责不漏，人负责判断。

### 6.3 人工抽查清单（每幕交付前逐项打勾）

- [ ] 主角全程站立合理，没有凭空坐/凭空多出家具
- [ ] 每一帧文字可读：无遮挡、无同行相撞、无压脸
- [ ] 展品一组一组上：无两组主展品同屏交叠
- [ ] 倒水/切分/drop 等动作落在语义位置上
- [ ] 结论/问题块在提问区，不在地板区
- [ ] 最后一帧要点卡文字不出框

## 7. 子方案五：检查器环境固化 + 引擎怪癖清单

### 7.1 insightcheck 必须跑得起来

第一版最大的教训之一：项目有现成的硬指标检查器（`src/insightcheck.py`：文字面积 ≤40%、动态 ≥60%、静态字 ≤25%、四步分段、预测/规则次序），却因为环境缺浏览器而没跑成，于是「指标全过」的结论只来自桩测的近似值。

措施：新增一键脚本 `v5/tools/setup_check_env.sh`，固化本幕已验证可行的环境：

- 字体：LXGW WenKai + Kalam 落 `~/workspace/wb-fonts`（`WB_FONTS` 指过去）；
- `pyftsubset` 垫片（`python3 -m fontTools.subset`）落 `~/workspace/bin` 并入 PATH；
- 浏览器：playwright venv + Chrome-for-Testing 直装（playwright 官方下载通道在本环境多次出现「装完即丢」，直装 zip 落盘更可靠），`run_insightcheck.py` 以 `executable_path` 注入启动；
- 验收标准：`insightcheck --only=<幕名>` 输出 `不合格 0` 才算环境就绪。

**门禁**：交付说明必须附 insightcheck 的原始输出行。本幕修正版实测：`102.7s / 预测 1 / 规则 95.8（在预测后）/ 文字 12% / 动态 76% / 静态字 25% / 分段 11/39/25/25 / 不合格 0`。

注：静态字 ≤25% 这条靠「讲解中的展品加真实可见的动效（呼吸光圈、热气）并登记 C.motion 窗」达标——这是引擎的既定用法，不是刷指标：光圈本身就是给孩子的视觉信号。反之，**禁止**用无意义的 C.motion 空窗刷动态/静态字数据，评审时对照截图核验动效真实可见。

### 7.2 引擎怪癖清单（活文档，写场景前必读）

新增 `v5/ENGINE_NOTES.md`，把已付过学费的坑逐条登记（持续追加）：

1. actor 一旦有 `walk`，walk 帧会接管该 actor 全部时间的帧选择——keys 表演与走路必须拆成不同 actor 用淡入淡出衔接；
2. `ref` 帧决定全员比例归一化，只能用中性站立帧（见 CAST.md）；
3. `schemaContainer` 的波浪宽度 = `2 × w × spread`，默认 spread=1.5 会溢出容器很多，必须显式验算；
4. count 徽章在 `bounded` 状态切换后约 0.5–1s 才完全弹出，截图验收要避开切换瞬间；
5. `K.prop` 的自绘动效**不**自动登记动态窗，必须配 `C.motion`，否则静态字指标与实际画面不符；
6. 朗读词块（say）固定在底部 y≈803–905，与地板区一切元素冲突，落位先查分区表；
7. narr 字幕条最高两行（约到 y=136），预测圆环固定在右上（1693,208）。

## 8. 落地步骤

| 期 | 内容 | 产物 | 成本 |
|---|---|---|---|
| 一期（立即） | 联系表 + CAST.md；分区规范入评审清单；截图工具入库；setup 脚本 + insightcheck 门禁；ENGINE_NOTES 建档（本文档第 3、4、5、7 节直接转入） | `v5/tools/cast_sheet.py`、`v5/sprites/CAST.md`、`v5/tools/shots.py`、`v5/tools/setup_check_env.sh`、`v5/ENGINE_NOTES.md` | 半天内，工具原型均已在本幕验证过 |
| 二期（一周内） | 重叠自动检测（fillText 拦截 + 包围盒求交 + 白名单），接入构建后自动跑，报警清单随截图一并产出 | `v5/tools/overlap_check.py` | 1–2 天 |
| 三期（持续） | 每幕交付执行第 6.3 节清单并归档截图；新坑随手追加 ENGINE_NOTES；新素材先更新 CAST.md | 流程习惯 | 每幕约多 10 分钟 |

## 9. 验收标准（对本方案本身）

下一幕新场景（如 G03 可数性）按本方案走完一遍：交付物里能看到 CAST 引用记录、insightcheck 原始输出、约 20 帧截图与重叠报警销项表、抽查清单打勾——且用户抽查任意一帧无位置/遮挡问题，即算方案生效。
