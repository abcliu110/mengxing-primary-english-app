# 萌星 · 数据优化操作规程（检查 → 核对 → 搜索最佳讲法 → 更新 → 表达）

> 定位：把用户定的总要求——「动画重写的质量在于数据是否正确；概念要有高屋建瓴的理解；阐述方法要全网找最佳、最易于理解的引进；每个数据都检查、核对、搜索，然后更新；最后以动画更好地表达」——落成可执行、可验收的操作方法。
> 与《重写技术方案》分工：技术方案管架构与日常修改 SOP（其 §8）；本规程管**一条数据从旧库到新模型的全程处理**。两者冲突时以本规程的数据标准为准。

## 0. 总流水线（七道工序，缺一不放行）

```
①抽取登记 → ②正确性核查（概念层+内容层）→ ③裁定分级 → ④最佳讲法搜索与引进
→ ⑤更新入模（纲领→概念→主张→讲法）→ ⑥动画表达 → ⑦验证交付
```

每条数据在任何时刻必须能回答四个问题：**查过没有？裁定是什么？讲法从哪来？现在存在哪？** 回答不了 = 还在流水线外面，不许被动画引用。

## 1. 抽取登记

- **操作**：从旧库（主 HTML 的 20 个数据库、白板场景文件）按库抽取全部记录，转 JSON 暂存（已完成一轮：`~/workspace/content-audit/`）；白板台词去重后抽「带主张的句子」成清单。
- **登记字段**：每条数据一个临时 ID（库名+条目号+字段名），记录原文、出现位置、复用次数（同一说法在几幕/几卡出现——决定错误的影响面与修改优先级）。
- **产出**：待审清单。**通过标准**：可复现抽取（脚本重跑结果一致）；无「未登记先引用」。

## 2. 正确性核查（双层，独立审查员执行，不许自审）

### 2.1 概念层（先于内容层）
逐条问四问，任一不过即记概念问题：
1. 它声称的机制是真的吗，还是编的故事？（把习惯/识解说成物理必然 = 假机制）
2. 它的类型名实相符吗？（联想标成词源、倾向标成定律、口诀标成原理 = 名实不符）
3. 它的分类/框架在语言学上存在吗，还是自创名词包装？
4. 它的比喻会不会被孩子当真机制迁移到反例上翻车？

### 2.2 内容层
按数据类型查权威来源，**来源分级**（只认一、二级，三级仅作线索）：
| 类型 | 一级来源 | 二级来源 |
|---|---|---|
| 词源/构词 | Etymonline、OED | Wiktionary（查其引用）、词源词典 |
| 语法规则 | CGEL、Quirk《英语语法大全》、Swan《Practical English Usage》 | 剑桥/牛津语法参考 |
| 释义/音标/例句 | 牛津/剑桥/朗曼学习词典 | 大型语料库（COCA/BNC）例句 |
| 语音现象 | 语音学教材（ Ladefoged 等）、词典音标 | — |
| 教学讲法 | 同行评审研究（见工序 4） | 优质教材的处理方式 |

- **全称表述专项**：凡「都/一定/总是/凡是/绝不/必须」逐条强制找反例；找到一个合法反例，全称即降级为倾向并登记例外。
- **测验答案专项**：每道题的预设答案独立复算，防止「题对答案错」。
- **产出**：逐条核查记录（原文 / 查了什么源 / 结论）。**通过标准**：每条主张至少一个一级或二级来源支撑；无来源者自动进「存疑」格，不许默认成立。

## 3. 裁定分级

四级 + 严重度（高/中/低），与既有审计口径一致：
- **成立**：概念与内容都对 → 直接进工序 5。
- **基本成立**：对但有毛边（措辞、漏条件）→ 小修后进 5，修改点留痕。
- **过度简化**：方向对但会误导 → 必须降格表述（加「一般/大多数」、补关键例外）并换或补讲法，走 4 → 5。
- **错误**：概念假或事实错 → 禁止入模；先在工序 4 找正确框架与讲法，再走 5。原条目标记 superseded，不删（留痕防再犯）。
- **优先级**：按 严重度 × 复用次数 排序——高频播出的错台词最先处理。

## 4. 最佳讲法搜索与引进（每个概念簇必走，不许只凭经验拟定）

- **搜索协议**：每个概念簇至少查 **3 个独立来源**，含至少 1 个学术/教材级来源（认知语言学教学应用、学习科学文献、主流分级教材）。记录候选讲法 + 出处成「候选表」。
- **采纳四标准**（逐项打分，缺一不采）：
  1. **机制真实**——讲的是真机制，不是好记的假故事；
  2. **儿童可达**——6–12 岁能借生活经验进入（有具体经验锚点）；
  3. **可动画化**——能变成画面动作（对比、指点、镜头推拉、手势），不是只能嘴说；
  4. **边界清楚**——隐喻/类比能写明「哪里不像」，写不出边界的隐喻不采。
- **耳目一新但存疑者**：网上流行的新奇讲法（如短视频流行说法）默认按二级以下来源处理——机制真实性过不了工序 2 的核查标准，再抓人也只能降格为 mnemonic 并标注，不得承载概念。
- **产出**：该概念簇的「采用讲法卡」：采用讲法全文 + 方法类型（对比案例/功能目的/说话人视角/镜头看法/类比三步/动作体验/分层递进）+ 出处 + 失效边界 + 落选候选及落选理由。
- **全局基线**：阐述方法的总体排行榜以专项研究（学习科学 + 认知语言学进课堂实证）结论为准，逐概念搜索是在其框架内选型，不是各找各的。

## 5. 更新入模（写进知识模型，不是给旧库打补丁）

- **顺序铁律**：先纲领（领域核心看法）→ 后概念 → 再主张 → 讲法字段随主张同录。挂不上纲领的数据先停在待裁区。
- **记录规范**：按技术方案 §3——主张分型（rule/tendency/mnemonic/etymology）与必填字段、例外登记、`explain` 字段（方法/载体/失效边界）齐全；校验器（validate.py 同类规则）不过不入库。
- **更新包制度**：按领域分批更新（词汇一批、语法一批…），每批产出一份**更新包 diff**（原说法 → 新说法 + 裁定依据 + 讲法出处），供用户抽查拍板；拍板后该批才成为模型正式版本。
- **旧库处置**：旧条目不回写修正——新模型是唯一事实源；旧库在迁移期只读，条目以 superseded 指针指向新记录。

## 6. 动画表达

- 每幕先声明所属纲领与引用的记录 ID（只引用，不自创说法）；台词、卡片、测验全部由模型生成（多视图同源）。
- 讲法即分镜：`explain` 的方法决定节拍形态——对比案例 → 双屏对照；功能目的 → 角色使用场景；镜头看法 → 推拉镜头；动作体验 → 角色手势示范。讲法选错型，画面再好也打回。
- 物理动作走参照层：动作事实卡（真实参照提炼）约束原语，审查并排比对（见技术方案 §6 第 5 项）。

## 7. 验证交付（门禁清单，逐项打勾）

1. 数据侧：本幕引用记录全部「已裁定 + 已入模」，无一来自未审清单；
2. 内容校验 + 构建期不变量断言全过（语义标签关系检查）；
3. insightcheck 不合格 0；
4. 截图回归 + 独立逻辑审查（守恒/同一/因果/指称/时序）无未决项；
5. 参照对比审查（涉物理动作时）逐条对事实卡；
6. 旗舰幕：儿童误读探针通过，探针问题入库。
任一不过，问题回到对应工序（数据问题回 2–5，讲法问题回 4，表达问题回 6），不在动画层就地打补丁。

## 8. 角色与节奏

- **核查/搜索**：独立审查员（子代理）执行，与编写分离；**汇总复核**：主会话抽查高严重度项与全部「错误」级裁定；**拍板**：用户——纲领、错误级改判、每批更新包。
- **节奏**：以领域为批次滚动推进，一批 = 核查完 + 讲法定完 + 更新包批完，才开下一批动画生成。
