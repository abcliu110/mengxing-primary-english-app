# 白板动画技术升级方案：从「贴图换帧」到「弹簧 + 骨骼 + 程序化物质」

> 前提不变：内容（KNOW 知识点）一个字不改，只改呈现。约束不变：单文件 HTML 交付、场景是声明式数据、画面必须是时间的纯函数（可 seek、可截图验收、可跑 insightcheck）。
>
> 本方案回答一个问题：在这些约束内，动画为什么现在显得呆板，换什么技术能真正解决，且 558 幕的存量怎么迁移。

---

## 1. 现状诊断：呆板是结构性的，不是调参数能救的

对 v5 引擎（wb5.js + concept.js）实测的运动模型：

| 部位 | 现在的实现 | 为什么呆板 |
|---|---|---|
| 人物表情/动作 | 到时间戳**整帧替换** sprite（l_think → l_point），无中间帧 | 姿势是跳变的，人眼对生物运动最敏感，一眼假 |
| 走路 | 位置 lerp（`power1.inOut`）+ 每 50px 换一帧腿 | 匀速感、无重心起伏、无加减速的身体语言 |
| 待机 bob | `|sin| × −6px` 固定公式 | 全员同频同幅，像挂钟 |
| 弹出 pop | 固定 0.38s `back.out(2.4)`，所有元素同一种弹性 | 杯子和数字块一个手感——没有重量差异 |
| 物体 | emoji 字形 + schemaContainer 的正弦波浪线 | 「咖啡」是一条波浪线，不是液体；切分是整图换半图 |
| 镜头 | 固定 0.9s `power2.inOut` | 节奏由公式定死，不跟内容呼吸 |
| 声音 | 无（引擎层没有音效通道） | 动作没有听觉确认，pop/drop 是「哑」的 |

根源一句话：**现在的引擎里，运动 = 一组写死的公式；每个元素动法相同、与它是什么无关。** 好的动画恰恰相反：运动由「这是什么东西、多重、什么材质」决定。所以升级的重点不是换渲染库，而是给引擎装上三样它现在没有的东西：**物理（弹簧）、骨骼（人物分层）、物质（液体/粒子程序化生成）**。

## 2. 候选技术评估（为什么不换库）

| 路线 | 人物 | 物质 | 与现有流水线 | 成本/风险 | 结论 |
|---|---|---|---|---|---|
| **PixiJS/WebGL 全面重构** | 需自研 | shader 可做真液体 | 单文件体积 +600KB↑；文字排版、insightcheck 采样、截图验收全部重做 | 高：558 幕的场景 API 全部迁移 | ✗ 收益不在渲染层，否决 |
| **Lottie/Rive 编辑器制作** | 矢量关键帧，表现好 | 弱 | 每幕要在编辑器里手工做，与「场景=数据自动生成（50% 是 autoBuild）」根本冲突；中文字体与 KNOW 注入困难 | 高：生产方式推翻 | ✗ 只适合片头吉祥物，不适合正课 |
| **Spine 骨骼（商业）** | ★  industry 标准，骨骼混合最顺 | 无 | 运行时 +40KB；场景 API 可包裹；但 cast 现有美术是整图，需拆件重绘，且编辑器授权费 | 中：美术拆件是一次性大活 | △ 二期可选（见 4.2 乙案） |
| **Canvas 2D 原地演进（本方案）** | 分层纸娃娃骨骼（自研轻量） | 程序化液体/粒子（自研） | ★ 引擎、构建、检查、截图 QA 全部保留；新原语是**增量添加**，旧场景零改动可跑 | 低：纯代码，无授权费，体积 +30–60KB | ✅ **推荐** |

判断依据：这个项目的核心资产不是渲染，而是「内容数据 → 场景 → 硬指标检查」这条自动化流水线（558 幕、autoBuild、insightcheck）。任何换库方案都要先赔掉这条流水线，而呆板的原因不在 Canvas 2D 的能力上限——弹簧、骨骼、液体在 2D canvas 上全部可做，且都能保持 `frame = f(t)` 的确定性。

## 3. 推荐架构：在 wb5 上加三层

保留 wb5 的时间轴、K/C API、构建与检查不动，在 concept 层新增三个原语族。全部新原语遵守一条铁律：**任意时刻的画面只由 t 决定**（弹簧用解析解、液体用固定步长预演缓存、粒子用种子随机），seek 与截图验收不失效。

### 3.1 第一层：弹簧运动系统（解决「所有东西一个手感」）

- 把 pop/drop/slide 的固定时长缓动换成**解析阻尼弹簧**（闭式解，天然是 t 的函数，可 seek）：每个元素声明自己的物理人格——
  - 重物（杯子）：高刚度、低过冲，落点带一次 squash（压扁 8% 回弹）；
  - 轻物（数字块、-s 钩子）：低刚度、高过冲，落点摇摆两次才停；
  - 液体相关：临界阻尼，无过冲，慢起慢停。
- API 草案（场景写法基本不变）：

```js
C.drop(chip, t, x, y, { spring: 'light' });        // 原 drop，内部换弹簧
C.chip({ ..., pop: { spring: 'heavy', squash: .08 } });
K.spring({ stiffness: 170, damping: 14 });          // 全局可调，场景可覆盖
```

- 派生收益：anticipation（起跳前回缩）、follow-through（停后余摆）由弹簧自动产生，不用逐幕手写；bob 改为每人不同相位/幅度的弹簧噪声待机，挂钟感消失。

### 3.2 第二层：人物分层骨骼（解决「整帧跳变」）

不换美术风格，把现有 cast 线稿**拆成部件**做 2.5D 纸娃娃骨骼：

- 拆件（一次性美术活，每角色约半天）：头（含表情组：平静/思考/惊讶/笑，用现有整帧的头部裁切）、躯干、左臂、右臂（指向姿势单独一件）、双腿、道具（书/外套）。
- 骨骼原语：`K.rig('linda', { x, ground })`，动作用关键姿势之间的弹簧插值表达：

```js
rig.pose(t, 'think', { hand: 'chin' });   // 姿势间自动补间，不再整帧跳
rig.pose(t, 'point', { arm: 'right' });
rig.walk(t0, t1, x1);                      // 腿摆 + 重心起伏 + 手臂反摆，程序生成
```

- 表情切换保留现有整头图（思考气泡等图内元素随头部走），但切换发生在头部转动的中途，眼睛就不再觉得是「换人」。
- **乙案（二期）**：若纸娃娃的关节感仍不够，上 Spine 只替换 rig 层的内部实现，场景 API 不变——先验证需求再花钱，是这条路线的保险丝。

### 3.3 第三层：程序化物质（解决「波浪线冒充咖啡」）

本项目的概念（边界/流体/切分）恰好都是物质问题，用程序生成代替 emoji 与波浪线：

- **液体**：低分辨率网格（96×54）metaball 液体，构建/加载时以固定步长预演并缓存每 0.1s 的轮廓——倒出来是真的一滩（会摊开、会晃），倒进杯子被容器形状约束（与 schemaContainer 的边框联动：无边时摊平、有边时成形）。这直接就是「边界感」的概念本身，不再是比喻。
- **切分**：整物用 clip 蒙版沿刀线裂开成两半，各自带弹簧滑开 + 碎屑粒子；「切开还是它 / 切开就成两个」用真实的连通性呈现。
- **粒子**：蒸汽（已在用手写正弦，升级为上升消散粒子）、倒水水花、粉笔灰、星光，统一一个种子粒子原语 `C.particles({...})`。
- 性能账：液体网格 96×54 在中低端平板上 <2ms/帧，且只在有液体的拍子启用；粒子上限 300。

### 3.4 配套：声音层（引擎现在缺的一条腿）

WebAudio 程序合成音效（无音频文件，+0KB）：pop（正弦扫频）、落水（噪声滤波）、切（短噪声脉冲）、答对（双音上行）。场景只声明语义：`C.sfx(t, 'pour')`，与预测/揭晓等节点绑定。音量与静音遵守播放器现有设置。

## 4. 迁移路径（不推倒、不停课）

| 期 | 内容 | 验收 |
|---|---|---|
| 试点（1 幕） | 在 `fp_boundedness_1` 上做 v3：倒入段换真液体、Linda 换 rig、全部 drop/pop 换弹簧、加音效；KNOW 与分段不动 | insightcheck 仍 0 不合格；按《布局质量保障方案》的截图流程逐帧验收；与 v2 同帧并排对比给用户评审 |
| 一期 | 弹簧层与粒子层进 concept.js（旧场景零改动、自动受益于 pop/drop 内部替换）；rig 素材拆件完成 Linda + woman | 抽 5 幕旧场景重建对比，无回归（检查器 + 截图） |
| 二期 | 液体原语开放给全部流体类概念幕（G03 可数性等）；按使用频率逐幕迁移，不设全量期限 | 每迁移一幕走一遍交付门禁 |
| 三期（可选） | 评估纸娃娃关节感是否达标，不达标才启动 Spine 乙案 | 用户评审决定 |

风险与对策：

- **文件体积**：三层新增代码约 30–60KB（gzip 后），液体缓存只在内存不进文件；单文件总增幅 <5%，可接受。
- **确定性**：弹簧用解析解、液体预演用固定步长 + 固定种子、粒子用种子 PRNG——三者都保证同一 t 同一帧，截图 QA 与 insightcheck 不受影响（这是选型的硬门槛，任何做不到这一点的技术已在第 2 节被排除）。
- **低端设备**：液体/粒子设质量档（按设备像素比与帧率自动降级到静态轮廓），降级只影响质感不影响信息。
- **美术拆件**：只拆 Linda、woman 两人；拆件保留原线稿像素，不重绘，避免风格漂移。

## 5. 验收指标（怎么算「更好了」）

1. 硬指标不退步：试点幕 insightcheck 全项通过（文字 ≤40%、动态 ≥60%、静态字 ≤25%、分段达标）；
2. 运动可辨识：盲看试点幕任意 3 个动作帧，能说出「哪个重、哪个轻、哪个是液体」——手感差异是这次升级的目的本身；
3. 人物不再跳变：姿势切换帧序列里无整图突变（截图连拍核查）；
4. 概念更直白：液体段不用波浪线符号，孩子能直接描述「摊开了 / 被杯子圈住了」；
5. 成本可控：单幕迁移工时 ≤ 半天，旧场景零改动可跑。
