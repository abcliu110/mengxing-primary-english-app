## 1. 标准（统一使用）

每幕按 5 项打分，每项 0 / 1 / 2 分：

| # | 项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|---|
| c1 | 「啊哈」点 | 规则直接写出来、念一遍 | 脚本里有反差、对比或「化繁为简」，但先给了结论 | 先给现象（反差、预测后揭晓、因果演示、类比），孩子自己看出规律，最后才命名 |
| c2 | 动画承载意义 | 讲解员挥手、点头、思考，文字逐字写出；或角色动作和概念无关（讲 -ed 时踢球） | 角色演出本课动词，或手绘了概念图（时间轴、车厢），但只是摆放 | 运动本身就是概念：跨门线 = out，事件被推到时间轴后面 = 过去，-s 被 does 吸走 |
| c3 | 孩子参与 | 没有 | 只有节末「先想 3 秒」的套用题（规则讲完以后） | 讲规则**之前**先让孩子预测、找错，或留白 |
| c4 | 非模板 | 同板换词、串课、凑数搭配 | 共用框架，但本课内容是独立的 | 为本概念单独设计 |
| c5 | 画面 vs 文字 | 主要是手写文字 | 文字为主，但有和概念相关的图或道具 | 画面为主，文字只做标签 |

**判级规则**
- **A**：c1 = 2 且 c2 ≥ 1；或 c1 ≥ 1、c2 = 2、c3 ≥ 1。也就是孩子能自己发现，而且画面在帮他发现。
- **B**：达不到 A，但 c2 ≥ 1（演示型）；或 c1 ≥ 1 且 c3 ≥ 1，或 c1 = 2（脚本型）。
- **C**：其余。没有可发现的东西，画面也不承载意义。

**样本**
- 全部 495 幕自动幕（`autoBuild` 470 幕、`mindmapBuild` 25 幕）都用脚本解析了 ITEMS / ACTS，统计了板书、朗读、动作帧和预测题（`parse.js`、`grade.py`）。
- 逐条读完内容的有约 75 幕：每个模块至少 2 幕，大组 5–10 幕。万能动词 72 幕的旁白和例句全部过了一遍。13 幕手工幕（时态矩阵 5、过去式门派 4、形容词排序 4）读了源码。
- 从主 HTML 抽出 10 幕渲染成 8 帧联络表，目视核对：`tense_matrix-4`、`adj_order-0`、`vv_take_out-1`、`hd_g21-0`、`hd_fr01-0`、`fp_economy-0`、`hd_oral_sc07-2`、`hd_poly_g1_002-1`、`hd_mindmap-0`、`wo_grimm-0`。图在 `/workspace/work/insight_audit/shots/`。
- 同模板组按组判分，单幕有偏差的单独改分（见 `grade.py` 里的 OV 表）。

## 2. 全局证据：为什么几乎都落在 B / C

1. **一个引擎排了 92% 的幕。** 470 / 508 幕由 `v5/scenes/auto.js` 的 `autoBuild` 生成。它做的事只有一件：把 ITEMS 里的字一行行手写到 4 列 × N 行的白板上，镜头逐块推过去；右边站一个角色。例句里碰到动作词，角色就换 1–3 帧。引擎里**没有**箭头移动词块、时间轴、两画面对比、遮挡揭晓这类能承载概念的手段。
2. **几乎全是字。** 这 470 幕的 ITEMS 一共有 8,167 条板书（`w` / `m`）、1,474 句朗读，图形道具（`p`）只有 **26 条**，而且全是 emoji。
3. **讲解员姿势顶替动作。** 187 幕的动作帧只有讲解员通用姿势（`l_speak`、`l_think`、`l_point`、`l_books`、`l_idea`、`l_hand`）。§2.9 H「不做」明确禁止这样。
4. **画面描述写成了字幕，画面本身没画。**
   - 一词多义 51 幕，中文字幕是分镜说明，比如「第二幕【场景变形·登记造册】：售票员翻开一本座位登记册……」（`hd_poly_g1_002-1`），画面上只有讲解员和板书。
   - 21 幕板书写着「看中央实验台：直观观察……」（拼读、构词、易混词、语法总结），实验台从来没画出来。
   - `wo_grimm-0` 旁白说「把 pes 放进时光机，p 进去出来变成 f」，画面只有文字，开场还是一个提购物袋走路的男孩。
5. **同板换词。**
   - 一词多义 17 个词 × 3 幕，每组三幕的板书**完全相同**，只有底部字幕不同。
   - G07 / G08 / G09 / G10 / 代词总结共用同一块「主格 vs 宾格」板。G31 / G32 / G34 / How–What 总结共用「like 必用 What」板。G35 / G36 共用一块板。
   - 口语 144 幕全是「核心句 → 💡提示 → 对话第 1 / 2 / 3 轮」。
6. **预测题是模板加的。** 67 幕带「先想 3 秒」，全在节末、规则讲完之后，属于套用题，不是发现。

> 附带发现：决策 36 ①1 的「能量吸收器串板」在当前 `v5/scenes` 里已经修了（hd_g19–g30 各有本课的板）。下面三处还在：
> - ①3 截断：`hd_g05_1.js` 仍有「在中间垫一个鼻音 n 变成」「an elephant, an」这类断句。
> - ①4 G14 错误：`hd_g14_3.js` 仍写「IN (>1天长时段容器)…in the morning」。
> - ①2 G07–G10 串课。

### 3.1 拼读（4 幕：A 0 / B 0 / C 4）
- **hd_phonics-0（CVC -at 家族）**：标题、「看中央实验台：直观观察音素滑块碰撞合体」、「c-at(猫)·b-at·h-at…」、原理「a 永远发 /æ/」全是板书；整幕只有 1 句朗读，还是三幕共用的「c-at -> cat! cap -> cape! sheep vs ship!」。滑块没画，所以判 C。
- **hd_phonics-1（Magic E）**：板书写「不发音 e 把能量传给 a」，画面上没有 e 出现、a 变音的过程。讲解员用的是 l_cap 帧，和概念无关。判 C。
- **hd_phonics-3（拼写潜规则）**：四条规则逐条念，例句配 give 手势。没有让孩子先看出「have / give / love / five 都以 ve 结尾」。判 C。
- **改造思路**：「换车头」真的做成滑轨。-at 车厢固定，c / b / h / m 车头一个个开进来，每接一次念一次。第 5 次留空，让孩子自己念 r-at。Magic E 做成反差：先让孩子念 cap，再从右边滑进一个 e，a 的口型图从「大嘴 /æ/」跳成「字母名 /eɪ/」，同时问「e 自己发音了吗？」。

### 3.2 构词（6 幕：A 0 / B 3 / C 3）
- **hd_formation-0（合成词）**：「sun ☀️ + flower 🌸 = sunflower」写在板上，「看中央实验台」没画，讲解员做 l_idea 姿势。判 C。
- **irregular_plural-0（foot→feet）**：脚本好。古英语复数词尾 -i 像磁铁，把 oo 拉成 ee，后来磁铁掉了、变形留下。因果完整（c1 = 2），但画面是字加一个站着的 man / woman。判 B（脚本型）。
- **eight_endings-0**：「规则的小尾巴一共只有 8 个」有化繁为简的效果，节末有预测。8 条尾巴逐条写出。判 B。
- **改造思路**：不规则复数直接把「磁铁」画出来。foot 后面吸一块写着 -i 的磁铁，oo 两个圈被拉扁、变成 ee；磁铁掉下来，feet 留着。紧接着出 goose / tooth，**先停 3 秒**让孩子猜复数，再揭晓。

### 3.3 单词卡（1 个模板，覆盖 1425 词 × 3 幕：C）
- **wordcard_tpl-0**：`wordcard_items.js` 把词条字段拼成三块框（词源与音节、构词与搭配、汉英防坑）逐行手写。三幕只是三块框的顺序不同。动作帧全库共用 `l_books / l_read / l_think`（讲解员）。默认卡 apple 的搭配栏写的是「a apple / the apple / my apple」，记忆法是「a 像圆圆的苹果带着小叶子」（伪拆分）。孩子打开任何一个单词，都看到同一种「字 + 讲解员」。判 C。
- **改造思路**：单词卡只做一件有意义的事，**「一词一画面」**。例句里的动作或场景用场景角色演出来；然后给 3 秒「遮住英文，看图说词」。词源只在有真实词源的词上出（📜），没有就不出，不再用模板填满三块框。

### 3.4 语法 40 点（56 幕：A 0 / B 0 / C 56）
- **hd_g21-0（-ed 变形与发音）**：联络表 8 帧全是板书：「-ed 四条加法」「读音：清辅音后读 /t/…」「常错 stoped ✗」「口诀」。讲解员托腮思考，从头到尾没有一帧画面在解释。判 C。
- **hd_g14-0（in / on / at）**：标题「告别死记硬背！看懂空间图式」。实际是「in (三维容器内) / on (平面接触面) / at (精确坐标靶心)」三行字，加 📦🍎 两个 emoji，还露出「**三维空间几何镜头**」。第 3 幕（hd_g14-2）仍有「IN (>1天长时段容器)…in the morning」的错误。判 C。
- **hd_g07-0（主格 vs 宾格）**：板书写「⚡ 动词/介词转换门：穿过此门强制换宾格！」，门根本没画。同一块板被 G08、G09、G10、代词总结原样复用。判 C，而且串课。
- **改造思路**（这个模块最该重做，每点一个反差钩子）：
  - G07 主格宾格：画一扇写着 like 的门。He 从左边走进门，出来的时候衣服换成 him。再让 she 走一遍，**停住让孩子猜**出来是谁（her）。
  - G05 a / an：让讲解员连读「a apple」，嘴巴「卡住」画个结；中间塞进一个 n，变成顺滑的「an apple」。然后出 hour / useful 两张卡，**先猜**再揭晓（耳朵 vs 首字母的反差）。
  - G18 一般现在时：同一个 Leo，左边一周日历上每天 7:00 都有一个小圆点，右边是此刻的一张快照。问孩子：「every day」该指哪一边？
  - G37–G39 比较：两个人站在身高尺旁边。一样高时放 as…as；一个踮脚，tall 自动长出 -er；第三个人跳上台，冠军台上才出现 the -est。
- **全组共性**：每点只放一个「看现象 → 猜 → 命名」，规则文字压到最后一块金句卡。

### 3.5 时态矩阵（5 幕：A 0 / B 5 / C 0）
- **tense_matrix-4（现在完成时）**：全 App 画面最接近 A 的一幕。有手绘时间轴；「I lost my key / I have lost my key」配一扇门和「进不去门！」；「has lived for five years」画成 2021→现在的一段橙线。问题是先念公式「have/has + 过去分词」再给对比，揭晓顺序反了，所以 c1 只给 1 分。判 B（演示型）。
- **tense_matrix-2（一般过去时）**：老照片「咔嚓」定格、时间轴上指向 Past，概念图有了。但中段是 4 条拼写规则（规则 / y→i / 双写 / was-were），后面还有信号词表。判 B。
- **tense_matrix-0（一般现在时）**：开头钩子好（「同一个 play，为什么有时 plays、played、is playing」）。中段插了 ch / sh / -es 拼写规则，节奏被打断。判 B。
- **改造思路**：只调顺序就能升 A。先放两张图（钥匙丢了但门开着 vs 钥匙丢了门进不去），只给两句英文，问「哪句配哪张？」，揭晓后才讲 have 的本义是「现在手里有」。拼写规则挪去 ③2「词尾变化总表」，别塞进时态幕。

### 3.6 万能动词（74 幕：A 0 / B 69 / C 5）
- **vv_turn_off-0**：三帧专属动作「关电视」，和 turn off 一致；板书标签「触点贴合 → 触点断开」。动作对，但「off = 断开」是写出来的，不是看出来的。判 B（演示型）。
- **vv_take_out-1（take out ②）**：旁白和板书讲「He takes the dog out / 人和狗离开家」，联络表里却是一个**提着购物袋走路的男孩**，没有狗，没有家门线。全幕最后才写一行「共同点：OUT = 从里面到外面」。§2.9 样板要求的「跨门线那一刻弹出 out!」在这里完全没有。动作和句子对不上，降为 C。
- **vv_give_on-0 / -1**：「The window gives on the green park」是小学生不会用的古旧搭配（凑 6×6 格子凑出来的），判 C。同类：vv_take_on-0（扛包误用）、vv_turn_in-1（字幕「上交」，句子是 Time to turn in「去睡觉」）。
- **改造思路**：这个模块最大的「啊哈」在于**同一个小品词跨动词**，网格天然适合，但现在一格一幕地切开讲了。改成一个小品词一幕：画一条门线，take / get / look / put / turn 五个动作依次**跨过同一条线**，每跨一次弹「out!」；第 5 个先不演，让孩子猜「turn out the light 是什么方向？」。凑数格直接留空（决策 36 ①5 已定）。

### 3.7 框架语义（25 幕：A 0 / B 0 / C 25）
- **hd_fr01-0（buy）**：字幕「Taotao buys a storybook」，画面是妈妈拿裙子。板书「当前视角流向：买家 ➔ 商品｜句法结构公式 Buyer + buy + Goods」，只有一个角色，没有卖家，也没有钱。判 C。
- **hd_fr05-0（look at / listen to）**：「主动感知 vs 结果」写成公式，没有「看了但没看见」的反差画面。判 C。
- **hd_fr03-0（come / bring）**：「👦 小明 & 📓 作业本 ➡️」是 emoji 箭头，方向感全靠字。判 C。
- **改造思路**：框架语义天生就是「同一画面换镜头」。只画**一个**买卖场景（买家、卖家、书、钱，两条流向箭头），四幕都在这一个画面上做：buy 时镜头推到买家、书的箭头变橙；sell 时推到卖家；pay 时钱的箭头变橙；cost 时推到价签。最后一幕把四个动词贴纸打乱，让孩子拖到对应的角色身上。孩子会自己发现「事情没变，换的是谁当主语」。

### 3.8 格林定律 / 词源（29 幕：A 0 / B 7 / C 22）
- **wo_grimm-0（总述）**：脚本是全 App 最好的之一。「时光机：p 进去出来变成 f → foot；借来的 pedal 没进时光机，还是 p」，因果、反差、迁移题（pedestrian）都有，c1 = 2。可时光机只出现在旁白里，画面是逐行字加一个提购物袋走路的男孩，时长 338 秒。判 B（脚本型）。
- **wo_grimm_voiceless-0（p t k → f th h）**：先写规则「p → f」，再列 pater / father、pes / foot……10 对词，配「Point to your foot」「Nod your head」。孩子没有机会自己从词对里看出 p→f。判 C。
- **wo_rule_norman-0（诺曼 w ↔ 法语 g）**：7 行板书、1 句朗读（guard 配站立帧），没有钩子，也没有预测。16 幕 wo_rule 都是这种「规律名 → 2–3 对词 → 出处」的短卡。判 C。
- **改造思路**：把时光机真画出来做成「转盘」。左边投进拉丁词卡（pater、tres、cor），转盘一转，右边掉出英语词，但**掉出来之前停 3 秒让孩子猜**；第 4 张投 pedal 时故意绕开机器，出来还是 p，让孩子发现「借来的大词没进机器」。wo_rule 短卡改成「找不同」：并排放 war / guerre、ward / guard，让孩子圈出哪里不一样，再讲诺曼人。

### 3.9 口语场景（146 幕：A 0 / B 0 / C 146）
- **hd_oral_sc07-2（Can I try it on?）**：联络表里 8 帧有 6 帧是「对话第 n 轮 / 角色 A：… / 中文」三行字逐字写出；角色只是站着、换手势。💡 提示「代词 it 必须夹在 try 和 on 中间」写在板上，没有演示。判 C。
- **hd_oral_sc01-0（Nice to meet you）**：吴斌斌和 Sarah 两个角色只画了同一个男孩（审计 36 已指出）；三轮对话 + 「秒回 too」写成板书。判 C。
- **oral_func-0（礼貌阶梯）**：五级礼貌从直接到客气，内容有梯度，但五级只是逐条写，没有阶梯画面，也没有「你会选哪一级」。判 C（接近 B）。

### 3.10 思维导图（25 幕：A 0 / B 0 / C 25）
- **hd_mindmap-0（学校与学习）**：中心椭圆，枝叶一个个写出「bag 包、书包 / schoolbag / pencil box…」，每个叶子念一遍。结尾「常用搭配：Carry your bag / 评价形容词：a bag / the bag / my bag」是模板句。分组名「包和盒 / 各种笔 / 电器和灯」只按词义分类，没有任何思考。判 C。

- **改造思路**：导图的价值在「为什么这几个词在一起」。每一枝先只画 3 个图（铅笔、钢笔、蜡笔），问「它们有什么共同点？」，揭晓「都能写字 → 都用 write / draw」；最后一个叶子先空着，让孩子从 3 张图里挑一个该挂哪枝（找错：故意把 ruler 挂在「各种笔」里）。

### 3.11 底层原理 / 第一性原理（22 幕：A 0 / B 22 / C 0；画面层面全是 C）

### 3.12 隐喻（4 幕：A 0 / B 3 / C 1）

## 5. 根本原因（流程 / 模板 / 验收）

1. **v5.1 标准是为「一句一动作」设计的，却被套到了所有内容上。** §2.9 的样板是「He takes the dog out.」：立场景 → 动词重音 → 跨边界 → 总结，验的是动作的运动品质。决策 32 要求「前面所有白板都按这个标准重画」，可语法规则、词源、导图、口语都不是「一个动作」，结果只能退化成「字 + 角色做个动作」。
2. **R1「一字不差、零丢失」把旧文字原样搬上了黑板。** `gen_auto.py` 读旧 HD 剧场导出的清单，把每条字幕、白板字、朗读原样写进 ITEMS；`REDRAW_V5.md` 用「R1 91/91」这种计数验收完成度。旧稿里描述画面的句子（「看中央实验台」「时光机」「售票员翻开登记册」）也被当成文字搬了过来，画面本身没人画。
3. **一个通用引擎排 92% 的幕。** `autoBuild` 只会排字，加一个右侧角色，没有任何「概念动画」原语（移动词块、对比分屏、遮挡揭晓、时间轴推移）。内容再好，出来也是同一种画面。
4. **R4 / R4v2「动词必须演出来」变成了凑动作。** 句子里有 play 就踢球、有 played 就踢球，哪怕这一课讲的是 -ed 读音。187 幕干脆只用讲解员姿势。§2.9 H 禁止讲解员手势顶替动作，但没有检查项拦住。
5. **验收清单里没有「启发性」这一项。** SOP §17 的 12 条验收全是工艺：确定性、帧、弹字时机、颜色、朗读、体积、报错、R2 / R4。第 11 条「静音盲测」问的是「谁对什么做了什么」，不是「孩子看完能不能说出规律」。§2.7 M1–M12 也全是运动法则。没有一条问「画面是否让孩子自己发现」。
6. **数据驱动批量生成，造成模板化。** 一词多义（17 词 × 3 幕同板）、口语（144 幕同版式）、导图（25 幕同版式）、单词卡（1425 词同模板）、万能动词（6×6 硬凑出 give on、give down）都是「先定格子再填数据」。决策 36 新加的「节末 3 秒预测题」也是统一追加的，67 幕全在规则讲完之后，属于套用，不是发现。

**流程上的修正建议**
- 给每幕加一张「啊哈卡」作为分镜第 0 步：孩子先看到什么现象 → 猜什么 → 揭晓什么 → 最后才出规则名。写不出来就不做动画，改用要点卡。
- 验收加一条「**遮字幕测**」：不看字幕、不听旁白，只看画面，孩子能说出这一课的规律吗？
- 引擎补概念原语：词块移动 / 换装、并排对比、遮挡揭晓、时间轴推移、拖放挂钩。把 auto.js 的「字 + 人」降级为兜底，不再当主力。
- R1 改成「知识点零丢失」，不再要求「文字一字不差上黑板」。规则文字进要点卡或字幕，不上板。

## 6. 结论（≤300 字）

App 里共有 508 幕白板动画：A 0 幕，B 147 幕（29%），C 361 幕（71%）。B 里有一半，「啊哈」只在旁白里，画面仍是逐行手写字。用户的判断成立：
- 口语、语法 40 点、一词多义、思维导图、框架语义、拼读、单词卡这几个模块 100% 是 C。
- 格林定律、底层原理、中英对照的脚本确实有好点子（时光机、6 种读音只看声带、两个国王），但都没画成画面。

根本原因有三：
- **流程**：v5.1 标准是为「一句一动作」设计的，却被批量套到所有内容上；R1「一字不差」又把旧文字原样搬上了黑板。
- **模板**：92% 的幕由同一个「字 + 右侧角色」引擎生成，没有任何概念动画手段。
- **验收**：12 条全查工艺，没有一条查「孩子能不能自己看出规律」。
