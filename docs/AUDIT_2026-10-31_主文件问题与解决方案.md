## 二、逐项说明与解决方案

### 1（P0）「继续上次」恢复到自测引擎会崩溃

**复现**（已用无头浏览器复现）：

1. 任意入口开始一次自测（`startQuizSession(...)`）。
2. 刷新页面或关掉再打开，回到首页。
3. 首页按钮显示「▶ 继续上次 🎯 自测闯关引擎 › …」，点击。
4. 控制台报 `TypeError: Cannot read properties of null (reading 'prompt')`，页面停在首页，按钮没反应。

直接 `navigateTo('quiz_engine')`（不带题目）也是同样的错误。

**原因**：`noteLastView()`（约 8632 行）把 `quiz_engine` 和 `{domain, title}` 记进了 `appState.lastView`，但题目在内存里的 `quizState`（`itemIds`、`currentQ`），刷新后就没了。`homeResumeLast()` 只调 `navigateTo(lv.screen, lv.params)`，`renderQuizEngineView()`（约 5187 行）没检查 `quizState.currentQ` 就去读 `.prompt`。

**解决方案**（两处都改，互为保险）：

```js
// ① noteLastView：自测是临时会话，不记成「上次位置」（保留进入自测前的页面）
if (sc === "quiz_engine") return;   // 放在 const sc = ... 之后

// ② renderQuizEngineView 开头加守卫：没有题目就回到综合自测入口
function renderQuizEngineView() {
  const st = quizState;
  if (!st || !st.currentQ || !(st.itemIds || []).length) {
    navigateTo("self_test");   // 或按 currentView.params.domain 重新出题
    return;
  }
  ...
}
```

老用户的 `appState.lastView` 里可能已经存了 `quiz_engine`，②能兜住；也可以在 `sanitizeAppState()` 里把 `lastView.screen === "quiz_engine"` 清掉。

**回归**：新增检查——28 个路由都用空参数 `navigateTo()` 一遍，并把 `lastView` 设成每个路由后点「继续上次」，要求 0 报错。加进 `runall.py`。

### 2（P1）词库占位内容大面积存在

**现状**（用 `VOCAB_DB` + `VOCAB_HEAVY_JSON` 合并后统计，共 1567 词）：

| 占位类型 | 词数 | 例子 |
|---|---|---|
| 例句是 `Let's learn and use "X" in a sentence!` | 445（其中 420 词例句和义项例句都是它） | — |
| 例句 / 搭配是 `Morph form: X` | 54 | `was` |
| 记忆锦囊是「记忆锦囊：属于【…】高频核心词」 | 445 | — |
| 形容词搭配只有「a / the / my + 本词」 | 924 | — |

典型坏词条 `V6_MORPH_26`（was）：例句 `Morph form: was`，词源字段写的是「考场必考不规则/拼写变形词」，`freq_rank` 8465（实际是最高频前 20 的词），`is_function_word: false`，`sight_type: decodable`（was 恰恰是要整体认读的视觉词），主题是「v6扩展词库」。这条让 `app_check8` 报 `BAD 占位`，是本次 runall 里唯一的 App 内容失败项。

这些对应交接文档里还没做的 35-A3（占位例句）、35-A4（模板搭配）、R37-03（模板填充）。

**解决方案**：

1. **短期止血（半天）**：渲染层统一过滤占位。已有 `placeholderTip()` 处理记忆锦囊，扩展成 `isPlaceholderExample()` / `isPlaceholderColloc()`，词卡、导图、测验题干遇到占位就不显示该栏（不要显示假内容）。`app_check8` 先恢复通过。
2. **中期补数据（按道 1 顺序）**：
   - A3 例句：优先课本原句，其次 Tatoeba 等 CC 授权句库，按年级限制词汇；每词 1 句，生成 JSON 后 `patch_*.py` 写入，人工抽检 10%。
   - A4 搭配：从例句库反抽真实搭配，抽不到的留空，不再用「a/the/my + 词」。
   - 变形词（54 个 `Morph form`）：不单独成词条，并到原形的 `irregular_info`（如 `be → am/is/are/was/were`），用 `WORD_ALIAS` 让搜索仍能找到；同时修正 `freq_rank`、`is_function_word`、`sight_type`。
3. **防回退**：新增 `datacheck.py`，把上面 4 类占位的计数做成门槛（只许减少），入 runall。

### 3（P1）手机返回键会直接离开应用

**现状**：全文件 `pushState` / `popstate` / `hashchange` 都是 0 次。页面切换只改内存里的 `currentView`。手机上按系统返回键或侧滑返回，浏览器会退回到上一个网页（或关掉标签页）；刷新也只能回首页。顶部虽然有「返回上一步」按钮，但孩子更习惯用系统返回。

**解决方案**：在 `navigateTo` 里接入浏览器历史，用 hash 兼容 `file://` 双击打开。

```js
// navigateTo 末尾（非回放时）
if (!opts || !opts.fromHistory) {
  const st = { screen, params: params || {} };
  history.pushState(st, "", "#" + encodeURIComponent(JSON.stringify(st)));
}

window.addEventListener("popstate", e => {
  const st = e.state || { screen: "home", params: {} };
  if (st.screen === "quiz_engine") { navigateTo("self_test", {}, { fromHistory: true }); return; }
  navigateTo(st.screen, st.params, { fromHistory: true });
});

// 启动时：有 hash 就还原，没有就 replaceState 成首页
```

要点：首页 `replaceState` 不 `pushState`；白板 iframe 全屏、弹窗打开时，先让返回键关闭弹窗 / 退出全屏，再退页面；`quiz_engine` 不进历史（同第 1 条）。回归：手机视口下进 3 层页面，连按 3 次 `page.goBack()` 应依次回到上一层，第 4 次才离开。

### 4（P1）本机回归工具链跑不起来

本次在你的 Windows 机器上跑 `runall.py`：27 项通过，4 项不通过。其中只有 `app_check8` 是 App 真问题（见第 2 条），其余是环境问题：

| 现象 | 原因 | 解决 |
|---|---|---|
| 直接运行 `runall.py` 崩溃：`UnicodeDecodeError: 'gbk'` → `TypeError: NoneType + str` | `subprocess.run(text=True)` 默认按 GBK 解码子进程输出 | `runall.py` 第 56 行改成 `subprocess.run(..., encoding="utf-8", errors="replace")`；其他检查脚本同理。临时绕过：先设 `$env:PYTHONUTF8="1"` |
| `phoncheck`、`kebiaocheck` 报 `JSONDecodeError` | `vocab_extract.js` 用 `s.indexOf('];\n')` 找词库结尾；本机 `core.autocrlf=true`，检出文件是 CRLF（`git ls-files --eol` 显示 `i/lf w/crlf`），找不到 → 词库没解析出来。所有依赖 `vocab_extract.js` 的生成脚本都会坏 | ① `vocab_extract.js` 读入后先 `.replace(/\r\n/g, "\n")`；② 仓库加 `.gitattributes`：`* text=auto eol=lf`，再 `git add --renormalize .` 提交一次，让 Windows 和 Linux 检出一致。补丁脚本里凡是按 `\n` 写锚点的，同样受益 |
| `insightcheck` 打包失败 `ERR_MODULE_NOT_FOUND` | `v5/build.mjs` 依赖 `esbuild`，本机没有 `node_modules`；脚本还写死 `/tmp/insightcheck`；字体子集化要 `pyftsubset` | 在 `docs/whiteboard/v5/` 加 `package.json`（锁定 esbuild 版本）+ `npm ci`；路径改 `tempfile.gettempdir()`；`pip install fonttools`；在 SOP 里写一段「Windows 首次准备」 |

另外，完整 runall 要 10 分钟左右，通过 MCP 直接跑会超时，需要后台运行再读日志（本次就是这么跑的）。

### 5（P1）学习进度容易静默丢失

**现状**：

- 进度只存在 `localStorage` 的 `mengxing_v1_1_state`。`saveAppState()` 写入失败只 `console.warn`，家长和孩子都看不到。
- 双击打开的 `file://` 页面，存储跟文件路径绑定：文件挪个位置、换个文件名、从微信重新下载一份，进度就「没了」。
- 没调用 `navigator.storage.persist()`，浏览器清理空间时可能被一起清掉。
- 每条单词 / 语法记录的 `streakDays` 日期数组只增不减，长期使用会越来越大。

**解决方案**：

1. 写入失败时，顶栏显示一次性提示「进度没保存上，请到家长门导出备份」。
2. 启动时 `navigator.storage && navigator.storage.persist && navigator.storage.persist()`。
3. 家长门显示「上次导出：x 天前」，超过 7 天在首页轻提示一次。
4. 首页检测「进度为空但像是老用户」（比如有 `ttsVoice_en`、`wbVoice` 等其他键）时，提示「是不是换了文件位置？可以导入备份」。
5. `streakDays` 只保留最近 60 天。

### 6（P2）文件体积 16.2 MB

**构成**：

| 部分 | 大小 |
|---|---|
| 白板按需模块（881 段 `text/plain`） | 12.4 MB（其中 372 张 webp 图 base64 共 9.9 MB，占全文件 61%；最大一段 `wb5blob-252d…` 0.94 MB） |
| 主脚本 | 1.66 MB |
| `VOCAB_HEAVY_JSON` | 1.59 MB |
| `GRAMMAR_EX_JSON` / `ETYM_DB_JSON` | 0.23 MB / 0.09 MB |
| 样式 | 0.05 MB |

**实测**：桌面 DOMContentLoaded 0.21 s，手机视口 + CPU 降速 4 倍 1.3 s，JS 堆 20 MB。按需加载做得好，**打开速度不是问题**；问题在**分发和存储**：16 MB 的 HTML 在微信里转发、用手机内置浏览器打开都偏慢，每次提交仓库多存一份。图片已经没有重复（372 张全部不同）。

**解决方案**（按收益排序）：

1. 图片再压一轮：统一最长边（白板显示尺寸的 2 倍即可）、webp 质量 70，或改 AVIF。预计 9.9 MB → 4–5 MB。
2. 出两个版本：「完整版」（含全部白板图）和「轻量版」（白板图换成矢量 / 文字占位），轻量版目标 < 6 MB，用于微信转发。由 `embed_app.py` 一键生成，不额外维护。
3. 长期：如果以后放到网上，改成 PWA（manifest + service worker），图片拆成单独文件缓存。

### 7（P2）仓库：提交说明乱码、体积大

- 433 条提交里有 **337 条**提交说明不是合法 UTF-8（GBK 写入），包括最新的 `7d83e01`、`7e5cb9e`、`f63d69e`。
- `.git` 约 520 MB：松散对象 200 MB、17 个包 318 MB，另有一个中断留下的 `tmp_pack_s0yejb`（36 MB）。

**解决方案**（都不改写历史、不强推）：

1. 中文提交说明一律写到 UTF-8 文件，再 `git commit -F 文件`；并设 `git config i18n.commitEncoding utf-8`、`git config i18n.logOutputEncoding utf-8`。
2. 在 CHANGELOG 里给乱码提交补一份「提交号 → 中文说明」对照（CHANGELOG 已经逐条记录了，只需标出提交号）。
3. 执行 `git gc`（会清掉残留临时包、合并松散对象），预计能省 200 MB 以上。

### 8（P2）可访问性

- 124 个 `<div>` / `<span>` 带 `onclick` 当按钮用，全文件 `tabindex` 0 处、`role=` 0 处、`aria-` 2 处。键盘用户（Tab / 回车）和读屏软件点不到这些入口。
- 没有 `prefers-reduced-motion` 适配，白板动画、弹出效果对动画敏感的孩子不友好。

**解决方案**：能改成 `<button type="button">` 的直接改（样式加 `all: unset` 后复用原 class）；改不了的补 `role="button" tabindex="0"`，并用一个全局 `keydown` 委托把回车 / 空格转成点击。加一段 `@media (prefers-reduced-motion: reduce)`，关掉装饰性动画、白板默认「逐步翻页」而非连续播放。新增检查进 runall：`div/span[onclick]` 计数只许减少。

### 9（P2）内联事件与 HTML 拼接

- 419 处内联事件属性（`onclick=` 等），114 处 `innerHTML` 赋值 + 15 处 `insertAdjacentHTML`，都是字符串拼接。
- 转义方式不统一：`attrEscape()` 只转 `& " <`，不转 `'` 和 `>`；约 4689 行语法游乐场用 `item.explain.replace(/'/g, "")` 直接删掉撇号来避免报错，结果讲解文字被改（如 don't → dont）。

**解决方案**：

1. 新代码一律用 `data-*` 属性 + 事件委托（README 已建议 `data-speak`），不再往 `onclick` 里塞文本。
2. 提供 `escHtml()`（转 `& < > " '`）和 `escAttr()`，替换掉临时的 `.replace(/'/g, "")`。
3. 加 lint：`onclick="...${` 里出现未经 `attrEscape(JSON.stringify(...))` 包裹的变量就报错。存量 419 处按模块逐步迁移，不必一次改完。
