# 词源数据修复标准（主会话制定，所有批次统一执行）

背景：独立审计判定 verified 数据有三病——① 原义字段拿今义/词根义冒充；② 语义路径 how 字段模板化（1,817 步里 5 个套话占 98.2%）；③ 待核门过严（另行处理）。本轮只修已 verified 的 801 条的三个字段：`original_meaning`、`semantic_path`（含各步 meaning/period/how）、`mechanism_sentence`。

数据文件：`/tmp/mengxing2/laws-prototype/model/etymology.json`（只读！产出写补丁文件，不直接改它）。
证据缓存：`~/workspace/etym-work/etymo/`（Etymonline）、`~/workspace/etym-work/wikt/`（Wiktionary）、`~/workspace/etym-work/ox/`（牛津）。一切改动必须能在缓存原文里找到依据，**不许凭语言模型记忆写词源事实**。

## 标准一：original_meaning（原义）
- 定义：这个词的谱系里**最早见载的那个意思**，且必须等于 `semantic_path[0].meaning`（两者修完后逐字一致或仅标点差异）。
- 取法：来源链里**最早的历史词形**（希腊/拉丁/古法语/古英语等真实词）的 gloss。例如 school 的原义取希腊语 skholē 的「闲暇」，pen 取 penna 的「羽毛」。
- 三禁：
  1. 禁拿印欧词根的 gloss 当原义（词根是学者重构的，不是词；school 原义写「握住」就是此病）。链首是词根时，原义仍取它往下第一个历史词的义。
  2. 禁拿后起义/比喻义/今义当原义（circle 原义写「兴趣中心的一群人」、ton 原义写「吨」都是此病）。按来源原文的年代顺序，取最早出现的那个义。
  3. 禁把两个同形异词的义并列（gnome 原义「地精；格言」是此病）。另一个词的义只能进 disputes 登记，原义只留本词的。
- 若现行 semantic_path 第一站本身就是后起义，说明路径起点错了，按来源的义项编年重排路径（见标准二），原义随之改正。

## 标准二：semantic_path（语义路径）
- 各站 meaning/period 以来源原文的义项编年为准（Etymonline 词条正文通常按年代叙述义的出现；Wiktionary/牛津互证）。现行路径若与原文编年矛盾（站点缺失、顺序颠倒、把晚期义排到前面），按原文重建站点，但**不许虚构原文没有的义或年代**；原文没给年代的站点 period 写「来源未注年代」。
- 站数可增可减，增减必须在补丁的 changes 里逐项说明依据。

## 标准三：how（机制，本轮重点）
- 每一步（第一站除外）的 how 必须写**这个词在这一步实际发生的变化**，大白话，至少包含：变化的内容（从什么义到什么义、靠什么联系桥接），来源支持时点名机制类别（借代、转喻、比喻、泛化、专化、词义扩大/缩小、感情色彩变化等）。
  - 合格例（school 第二步）：「闲暇时最正经的消遣是聚在一起讲学讨论，『闲暇』就转指『用闲暇做的讨论』——时间转指在那段时间里做的事（转喻）。」
  - 合格例（pen 第二步）：「羽毛做的笔就叫 penna 的后代词，后来笔换成芦苇、金属、塑料，名字被保留下来——材料变了，名字泛化到一切同类工具。」
- **禁用套话**（出现任何一条即整条不合格）：「最早的意思（本义）」（第一站 how 除外，第一站统一写「最早见载的意思」）、「进入英语以后，意思又慢慢变了，变成今天这样」、「一直传到今天，意思没变」、「意思变了（和上一站对比着看）」、「意思没变，跟着词一起传下来」，以及任何不点名本词义项内容的泛化句。
- 来源确实没有交代某一步机制的，how 写「来源未交代这一步是怎么变的」——如实留白，**不许编机制**。这类留白要在批次回报里计数。
- 第一步 how 统一写「最早见载的意思」。

## 标准四：mechanism_sentence（机制句）
- 一句话说清这个词最核心的那次变化及其缘由（人话，小学生家长能读懂）。不是罗列各站义项。
  - 合格例（lead，現行已是好句，保留类）：「lead 的老祖宗是『走』：lǣdan 是『让别人跟着自己往前走』，所以 lead 是带路、引领。」
- 现行句若只是「意思从『X』开始一站一站变：A → B → C」式罗列，必须重写；若已写出机制与缘由，保留并在补丁里标 keep。

## 纪律
- 同形异词筛保持开启：路径与原义必须属于 wordbank 里这个词的义项；其他同形词只进 disputes，不进路径。
- 不动字段：source_chain（唯一例外：某站 gloss 本身就是原义病的载体时可按原文订正 gloss，并在 changes 注明）、first_attested、sources、evidence_grade、status、story_hooks、modern_meanings_link。若发现 source_chain 本身串档或明显错误，**不要动**，记入补丁的 chain_flags，主会话处置。
- 民间词源筛保持开启：叙事再动听也要有原文依据。

## 产出格式（每批一个文件）
`~/workspace/etym-work/repair/batch<N>_patch.json`：
```json
{"<word>": {"original_meaning": "...", "semantic_path": [{"meaning": "...", "period": "...", "how": "..."}], "mechanism_sentence": "...", "changes": ["改了什么，依据哪家原文哪句"], "evidence": ["Etymonline: \"...\"", "Wiktionary: ..."], "chain_flags": []}}
```
- 批次内每个词都要有一条补丁（哪怕结论是全字段 keep，也要写明 keep 与核对依据）。
- 回报：处理词数、原义改正数、路径重建数、how 重写数、机制留白数、mechanism_sentence 重写/保留数、chain_flags 清单。
