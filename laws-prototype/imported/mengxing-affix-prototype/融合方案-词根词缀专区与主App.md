# 融合方案：词根词缀专区 × 主 App 构词模块

目标：把规律版原型（laws-prototype）的「词根词缀专区」与 V 组相关规律（V-15、V-30、V-33～V-39 等），融进主 App（萌星小学英语_最终合并版.html）的构词模块。不新建区、不复制页面，同一条规律只在一个地方讲透，同一份词表只由数据生成。

## 一、融合架构（三层）

1. **纪律层**：V-15「先认零件，再猜全词」+ 透明度谱，做构词模块全区总纪律卡，置于所有页签之上；V-39 导学细则置于其下，完整教学说明入家长门（成人层）。
2. **规律层**：V-33～V-39 规律页（已出调整原型 v1），负责讲机制，全 App 只讲一次；专区明细页讲解段一律引用规律原文并标注出处，不改写。
3. **索引层**：词根词缀专区的 4 主 + 2 辅面板，落进主 App 现有构词页签升级，不另起导航。

## 二、页面映射（现有页签 → 融合后）

明细页统一为一种模板（规律页与零件页共用，两个入口互链）：
讲解引用块（对应 V 条原文）→ 家族全词表 A–Z（每词带透明度点，拼写/同化变化就地标在词上）→ 义项分工 → 易混对手 → 假拆名单（附裁定理由与出处）→ 练习。
练习统一两段式（V-30 口径）：先只给零件猜（六成线），再给语境猜（八成线），分开计分；假拆辨伪题源 = pending 清单与 V-38 三型；答错只提示回讲解段。

## 三、数据融合（真正的工程量，先于页面）

1. **导入结构化字段**：原型版挂接表（基底 159 + 扩充 388 = 合并态可拆 547 条）导入主词库：每词补 `morphemes`（prefix/root/suffix 三槽 + gloss + 透明度）和 `morph_class`（split/whole/nosplit/form 四类）。按英文词形对齐（两版词库编号体系不同，不按 id 按词形），同词冲突以词库基底为准（扩充侧表与基底已校验零重叠）。
2. **生成而非手选**：所有面板成员由谓词对 morphemes 现算（WORDBANK 规则 6），禁止手选名单；生成后校验层比对条目正文成员数，零遗漏才过。
3. **口径冲突以定版为准**：主词库现有自由文本「积木拆词」与结构化数据冲突时，以原型版定版口径改卡面（如 butterfly 标半透明、butter 等禁拆名单整记）。禁拆名单逐词落实 morph_class=nosplit + 理由文本。
4. **缺词走补词流程**：空位前缀成员词、未入库词基等已在扩充数据登记待补，不在本波自造词条。

## 四、施工顺序与验收

- **第 0 步 口径冻结**：以 laws-prototype 的 vocab.yaml、vocab_MODEL.md、MORPH_ZONE_BLUEPRINT.md 为唯一依据；数字（547 条、95 页、67 词同化、各前缀计数）以合并态现算为准。
- **第一期 规律层**：AFFIX_LAWS_DB（V-33～V-39）+ 规律页签/详情 + 前缀页横幅与同化表 + 后缀页拆分与角标。（调整原型 v1 已示意）
- **第二期 数据层 + 索引层**：导入 morphemes/morph_class → 四个页签升级为面板 → 统一明细页模板 → 两段式练习。
- **第三期 纠错与联动**：单词卡随透明度数据自动纠偏（butterfly 等）→ 禁拆名单全库审计 → 拼读区拼写让路只互链不复制（规则正文归本区，源 V-37）→ 首页构词卡副标题更新。
- **注入方式**：数据块加起止标记 + 注入脚本（仿 insert_wb.py），改数据重跑脚本，不手工编辑主文件正文。
- **验收**：jscheck.py 通过；7 条规律齐；面板计数与谓词现算一致（抽 *spek- 19、un- 16、同化 67 三处对账）；例词全部可解析到主词库词条；规律页与零件页互链不落空；禁拆名单词在卡面无拆分讲法。

## 五、明确不做

- 不把专区在主 App 里另立顶层区（构词模块就是它的家）。
- 不复制规律文本到零件页（只引用）。
- 不把拼写让路规则在拼读区再立一份（只互链）。
- 不拿库外词填空位面板。
