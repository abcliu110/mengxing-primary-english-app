# 把规律加进 morphology-prototype-v1.html 的方法

> 对象：`laws-prototype/morphology-prototype-v1.html`（与 mengxing-prototype-v1.html 的 DATA 逐字节同源，生成产物）。
> 2026-11-02 对该文件 DATA 的实测结论是本方法的依据。

## 一、实测诊断：规律的现状不是「没有」，是「没有户口」

- DATA 结构：8 组、126 页（102 谓词页 + 主页/画廊/整词页等）、words 2,473、intro（=V-15 全文）、practice（=V-30 全文）。
- 111 页带 `laws` 数组，共 **114 份规律全文副本，只涉及 11 条规律**：
  V-21 ×44、V-36 ×25、V-33 ×20、V-32 ×11、GR-29 ×8、V-15/V-20/V-26/V-34/V-38/GR-28 各 ×1。
- **114 份副本按 id 逐字全等**（哈希校验，每条 distinct copies = 1）——收敛无损，这是能改存储形态的前提。
- 缺席者：**V-35、V-37 只以「对手规律」（opp）身份在各 2 页出现，没有正席**；V-39 只在 intro 导学里；
  V-34 只在 as-main 一页、V-38 只在 gl-main 一页。
- 文件没有规律列表、没有规律页路由：读一条规律，必须先找到引用它的页。

结论：不能再往页里塞副本（加一条新规律 = 再复制 N 份）。正确动作是先把规律的**存储形态**
从「页内嵌副本」改成「中央注册表 + 页内引用」，然后规律层自然长出来。

## 二、方法四步

### 第 1 步 · 立注册表 DATA.laws（收敛，不动一字）
- 114 份副本按 id 收敛为注册表：正席 13 条（原 11 条 + V-35/V-37 由 opp 转正，文本现成，零新写）
  + frame 2 条（V-15、V-30，本就在 intro/practice 槽位，角色标 frame，不进儿童列表正席）。
- 每条保留原字段（headline / kid / beats / statement / boundary / sources）逐字不动；
  新增两类字段：双坐标 `part`（部位）与 `station`（站号）；`pages` 反查索引（哪些页引用它，生成时自动算出，不手填）。

### 第 2 步 · 页内改引用（渲染结果不变）
- 126 页的 `laws` / `opp` 从全文对象瘦身为只存 id；lawBlock 改为按 id 查注册表渲染。
- 验收红线：126 页逐页渲染与改前 diff，除新增的「完整规律页 →」链接外应全等；冒烟 0 pageerror。
- 副产品：114 份全文 → 15 份，文件明显变小，后续改一条规律只改一处。

### 第 3 步 · 补缺与新增（入册，不入页）
- V-35 / V-37：第 1 步已转正，自动获得规律页（见第 4 步），pf-un/pf-in-neg 的对手关系改为引用正席。
- 新 2 条按同一 law 对象 schema 新写入册，标 `candidate`、编号待对账：
  恒常律（part=横切、station=形站），例词家族（sign/heal/magic/electric）从 words 按词形取；
  三读律（part=屈折、station=形站），给 if-plural / if-past 两页加引用即可落地，不新造页面。
- V-39 不入儿童注册表：它是教法，保持在 intro 导学 + 成人层（frame 处理），与现有结构一致。

### 第 4 步 · 给规律开门（只加一层，不动 8 组 126 页）
- **规律总览入口**：放在 intro（V-15）区之后、①组之前——位置即纪律：先过总纲，再看规律，再进数据页。
  列表双视图（按部位 / 按学习顺序，双坐标各管一个），每行带反查信息「在 N 页出现」。
- **规律页型**（新路由 `law-<id>`）：模板 = 注册表全文（kid → beats → statement → boundary）
  + 「这条规律出现在哪里」页列表（反查索引生成，点回谓词页）+ 按 station 的上一条/下一条。
  beats 渲染复用现 lawBlock 的函数，视觉与页内讲解一致。
- **页内闭环**：每个 lawBlock 底部加「完整规律页 →」；练习题里已有的「回看本页讲解（V-xx）」提示，
  可顺势升级为直达规律页的链接（题面数据不动，只改 hint 的渲染）。

## 三、纪律

- 改在生成源：规律文本源头仍是 `model/laws/vocab.yaml`，注册表由生成脚本从 yaml + 现有 DATA 收敛产出，
  两文件（morphology 与 laws 主文件）同步再生、保持 DATA 同源；**不手改两个 HTML 产物**。
- 顺序不可反：先收敛（第 1–2 步，纯结构、零内容变化），再补缺新增（第 3 步），最后开门（第 4 步）。
  每步独立验收、独立提交。

## 四、待拍板（不挡第 1 步）

1. 规律总览默认视图：按学习顺序（方案一）还是按部位（方案二）。
2. 新 2 条的 candidate 标记何时转正：与图鉴 428 条对账后回填编号。
