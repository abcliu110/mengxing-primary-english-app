# 备忘：词根词缀规律如何落进主应用（落法方案）

> 2026-11-03 凌晨。本文只做分析与方案，不含任何代码/数据改动。
> 口径：本文的「主文件」指现行集成范围内的 `laws-prototype/mengxing-prototype-v1.html`；根目录 18MB 出货 App 单独在 §二.6 与决策点 6 里处理。
> 数据口径一律以现行文件亲验为准；v2/v3/v4 原型的旧计数（547 可拆、空位待补设计）已过期，不再引用为依据。

---

## 一、现状亲验（先把事实摆清）

**1. 专区已经在主文件里，而且是完整的。**
`#v-morph` + `#v-morph-detail` 两段，首页（mz-index）构成：

- 「全库对账」卡：词库 2,473 词全部有归属——可拆 926 · 整词 1,199 · 禁拆 230 · 词形归原形 118 · 未分类 0；
- 「全区总纪律」卡（V-15 frame 全文）；
- 「🧩 这个区的 14 条规律」总览卡（见下）；
- 8 组面板的条目 chips：① 高频前缀 ② 后缀变身机 ③ 词根家族 ④ 屈折词尾 ⑤ 同化家族 ⑥ 复合词 ⑦ 假拆画廊 ⑧ 整词与禁拆（全库对账）；
- 「练习口径」卡（V-30 frame 全文）。

数据页共 126 页（102 个谓词页 + 假拆名单、整词对账等登记类页），零空页。每页结构统一：讲解（引用规律正文）→ 义项分工 → 易混对手 → 家族全词表（词卡带拆分式、透明度点、词库编号）→ 词源亲戚（只登记不拆）→ 两段式练习。

**2. 规律层已经在专区里落地，不是待建。**
LAWREG 共 16 条：正席 12 条（V-33/34/35/36/37/38、V-21/26/32、V-20、GR-28/29）+ 框架 2 条（V-15、V-30，不进儿童列表）+ 候选 2 条（NEW-C 恒常律、NEW-T 三读律，标「新 · 待对账」）。每条带双坐标（部位 × 站）。呈现件齐全：

- 总览卡双视图（按学习顺序 / 按部位），现行默认按学习顺序；
- 规律页：正式说法 + 机制 + 分组看看 + 「这条规律出现在哪里（N 页）」反查索引 + 按站序的上一条/下一条；
- 数据页内 lawBlock 只引用注册表正文，底部有「完整规律页 →」；从规律页跳数据页再返回，有回源页导航（不会把孩子扔回首页）。

**3. 跨区动线已有一半。**

- 词页（词汇模块 vcmod）→ 词根区：**已通且做得细**。词页有「拆分」入口，先给拆分登记原样 + 该词出现的词族页清单，再一键跳专区、打开对应页、高亮定位到那张词卡。
- 词源区词页 → 词根区：有「词根区看它一家 →」；专区首页有回词源区的整行入口（「拆词看结构，来历看词源」）。
- 词汇解码区 → 专区：列表底部有一行「词根词缀专区已独立成区 →」。

**4. 历史三代原型的主张（已大半被现行实现吸收）。**

- v2：纪律卡 + 抽样明细页 + 「单词卡联动示意」——验证页型与词卡联动；
- v3：三级结构（首页只放纪律卡 + 面板卡 + 规律入口 → 面板页折叠分组/搜索 → 明细页才出词表），计数是当时的 547/空位口径；
- v4：只剩一个未决问题——规律列表默认按学习顺序还是按部位（双变体对比）。
- 三代共同的旧前提「专区要搬进一个别的文件的构词模块」在现行范围内已不成立：专区与规律层都已在主文件内建成，三级结构与三级下钻（总览 → 面板 → 明细）在现行实现里基本就是这个形状。

## 二、问题重新定义

**一句话定义：数据与规律层都已建成且已在主文件内，剩下的不是「搬进来」的问题，而是同一批规律在主文件里有两三个户口、动线只通单向、招牌还停在旧时代的「名分与缝合」问题。**

具体剩六件：

**1. 规律双户口（最核心）。** V-33–V-39 在词汇解码区还有一整套旧呈现：解码区列表里 V-34–V-39 是普通 `data-law` 行，点开走的是 428 条体系的 LAWDATA 规律页（带病例/探针/成人层扩展的那套家具）；V-33 更特殊，走 LAWFLAG 映射到一个「已做深」单元 u-v33。同几条规律，在专区里又有 LAWREG 规律页（带分组看看、反查索引、站序导航）。两套正文同源于 vocab.yaml，但页面家具、导航、后续维护都是两份。孩子在解码区学的 V-36 和在专区学的 V-36 不是同一个页面，哪套是正文没有定论。GR-28/GR-29 同理：语法区有其 LAWDATA 页，专区有其 LAWREG 页与 if- 数据页，两边无导航互通。

**2. 动线单向。** 词页 → 词族页已通；反方向不通：专区的词卡（wordCard）除朗读外不可点，孩子在词族页看到一个词，没法回到它的词页（多义、例句、词源都在词页那侧）。专区像一座只能进不能回的桥。

**3. 招牌过期。** 首页专区卡还写「547 条拆分」（现行 926）；专区页副标题还写「本区内容与原词汇解码区内的词根词缀专区完全一致，只是独立成区」——这是当年镜像入口时代的文案，如今专区是正主、解码区那套才是旧表面，表述整个反了。渲染代码里还留着「0 · 待补词」的空位 chip 逻辑（v3/v4 空位设计的残留），现行谓词页已无空位。

**4. 候选两条落地不齐。** NEW-T 已挂到 if-past / if-plural 两页；NEW-C 的 `_pages` 为空——立了条、没落到任何数据页（它的例词家族 sign/heal/magic/electric 目前不在任何谓词页的承载面里）。两条编号与图鉴的对账另有专线在办，本备忘不重复。

**5. 规律总览的门只开在专区内。** 总览卡在专区首页中段，位置合理；但从解码区、语法区、词页出发的孩子，没有一条路是「先到规律页、再落数据页」的——规律层目前只是专区内部的导航，还不是全 App 的构词导航。

**6. 18MB 出货 App 是另一个问题，别混。** 根目录出货 App 仍是老构词模块（WORD_FORMATION_DB + 单渲染函数），无词根区、无规律层；旧目标文件（mengxing-affix-law-integration-into-main-app/GOAL.md）与旧《最终集成思考》写的都是把它换掉。但现行集成范围裁定只含 laws-prototype 目录。**这件事是否还活着，需要单独拍板**（决策点 6），不应默认塞回本轮。

## 三、落地方案（三案）

### A 案 · 专区坐正 + 动线缝合（小改）

**主张**：承认既成事实——专区就是主文件的构词中心；把双户口收成一个，把单向动线补成双向，把过期招牌换掉。不动任何数据与页型。

- **动什么**：
  1. 户口合并：V-33–V-39（含 GR-28/29 的处理见决策点 1）在词汇解码区的行改为指针行——点击直达专区 LAWREG 规律页；LAWDATA 里这几条保留为数据源与成人层深读的出处，但不再作为孩子的第一落点（u-v33 已做深单元保留，但入口改挂到 LAWREG 的 V-33 页内，作为「深读」链接，不再与规律页并列抢户口）。
  2. 反向链：专区词卡加点击 → 回词页（复用 vcmod 现成的词页打开路径，与正向 goMorph 高亮对称，做「回词页看全貌」）。
  3. 招牌修订：首页卡计数改 926（或动态取 DATA.stats.splits，免得下次再过期）；专区副标题改写为正主口径；删除/停用「0 · 待补词」空位渲染分支。
  4. 语法区 GR-28/GR-29 的 LAWDATA 页各加一枚 chip：「屈折词尾在词根区的家 →」直达 if- 面板。
  5. NEW-C 落地：按其例词家族新建/挂接承载（sign 家、heal 家、magic/electric 家可挂 ③ 词根家族组的亲戚登记面，或单立一页横切页），仍标「新 · 待对账」。
- **不动什么**：LAWREG、126 页、词库数据、专区页型、已集成的词源/代词/冠词/连词各区一概不动；解码区 V-01–V-32、V-40–V-45 的行与页不动。
- **孩子动线**：背词遇生词 → 词页拆分入口 → 词族页 → 页内规律块 → 完整规律页 → 反查索引落到别的词族页，或点词卡回词页看多义与词源。三条线（词页 / 词族页 / 规律页）任意两点可达。
- **规律层位置**：总览卡仍在专区首页（纪律卡之后、面板之前，位置即顺序：先纪律、再规律、后数据）；站序导航不变；与词页的接法是「规律页反查索引 ↔ 词族页 ↔ 词卡回词页」的三角，规律页不直接挂词页（保持规律层只管机制、不管单词全貌的分工）。
- **工程量与风险**：小。一批指针与文案改动 + 一条反向链 + NEW-C 一页承载；不动数据生成管线。风险主要是户口合并时 LAWDATA 侧的深读内容（病例/探针）别丢——靠「降为深读出处」而非删除来兜底。

### B 案 · 规律升维：规律层做构词脊梁（中改）

**主张**：把 LAWREG 从「专区内部导航」升为全 App 的构词入口层：凡是构词相关的到达，先过规律，再落数据。

- **动什么**：专区首页重排为「纪律卡 → 规律总览（升到首屏第一卡）→ 面板」；解码区 V-33–V-39 行、语法区 GR-28/29 行、词页拆分入口的第一落点全部改到 LAWREG 规律页，规律页的反查索引成为落数据页的唯一正门（现行词页 → 词族页的直达链降为规律页内的快捷方式）；站序成为全区默认学习路径，上一条/下一条跨页连续。
- **不动什么**：同 A 案，数据与页型不动，改的是入口层级与到达顺序。
- **孩子动线**：任何入口 → 先读规律（机制）→ 沿反查索引落到词族页 → 词卡回词页。规律页成为枢纽，去任何数据页都经过它。
- **规律层位置**：总览入口同时出现在专区首页首卡与解码区词缀组顶部（一处数据、两处引用）；站序导航与词页的接法同 A，但词页拆分入口先经规律页中转。
- **与已集成各区的关系**：词源区不受影响（其词页 → 词族页的链可保留直达，属「看亲戚」不是「学构词」，可豁免中转）；代词/冠词/连词区无关。
- **工程量与风险**：中。风险在教学节奏：规律页对低龄孩子偏抽象，强制中转可能让「我就想看这个词怎么拆」的即时需求多绕一页；且 B 案实质是把 A 案的缝合再推进一步，可在 A 落地后观察再升级，不必一步到位。

### C 案 · 撤销独立专区，回归解码区构词模块（大改）

**主张**：回到最早目标文件的字面构想——不设独立专区，词根词缀整体并回词汇解码区，成为解码区内的构词模块（解码区列表的词缀组就是它的门），`#v-morph` 段落撤销，首页卡与顶栏 pill 撤下。

- **动什么**：专区首页的对账卡、规律总览卡、8 组面板整体迁入解码区视图体系（渲染容器与返回栈要并入解码区的导航）；顶栏从十四区回十三区；所有指向 morph 的既有链（词页 goMorph、词源「看它一家」、解码区底部行）全部改锚。
- **不动什么**：LAWREG 与 126 页的数据与渲染逻辑可整体搬运，不重写。
- **孩子动线**：进解码区 → 词缀组 → 规律/面板 → 明细。与 V-01–V-45 同区，词汇学习一条线走完；代价是解码区列表更长、专区的独立品牌与「一键直达」消失。
- **规律层位置**：总览卡迁入解码区词缀组顶部；站序导航不变；词页接法同 A。
- **与已集成各区的关系**：词源区在导航序上本就紧挨专区（专区首页有词源整行入口），撤销专区后词源的「隔壁感」变弱，词源词页的「看它一家」要改挂解码区锚点；其余区无关。
- **工程量与风险**：大且收益存疑。这是否决已上线形态的回滚：专区独立成区是后来的明确决定，十四区的导航、首页卡、家长认知都已建立；C 案解决的只是「名分洁癖」，却要付出全量改锚与回归测试的代价，还会让 §二.1 的双户口问题以另一种形式留在解码区内部（LAWDATA 行与 LAWREG 页同区并列，更显眼）。**不建议**，列出只为把选项摆全。

## 四、推荐

**推荐 A 案。** 理由三条：

1. 剩余问题（§二）的性质是户口与动线，不是缺内容——A 案逐件对症（合并户口、补反向链、换招牌、给 NEW-C 落地），且每一件都可独立验收、独立回滚。
2. B 案的增量（规律强制中转）是教学节奏问题，没有观察数据支撑，先做 A、把规律页变成各入口可达的枢纽候选，再决定要不要升为必经之路，顺序更稳。
3. C 案回滚已建成的区级资产，成本最高、解决问题最少。

A 案内部建议顺序：先招牌与指针（户口合并 + 过期文案），再反向链，最后 NEW-C 承载页（可与编号对账线会合后一次落）。

## 五、需要 Stewart 拍板的决策点（6 个）

1. **规律正文户口**：V-33–V-39 的孩子第一落点定谁？
   - 甲：LAWREG 规律页为正文，解码区改指针、LAWDATA 降为深读出处（A 案取此）
   - 乙：维持双呈现，两边都算正文（现状，代价是长期双维护）
   - 丙：反过来以 LAWDATA 页为正文，专区规律页降为索引
   （GR-28/GR-29 是否同此办理，一并定。）
2. **专区名分**：独立专区保留（A/B 案）还是并回解码区（C 案）？
3. **规律列表默认视图**：现行实现默认「按学习顺序」（站序），v4 当年留的未决问题在此确认——保持站序默认，还是改「按部位」默认？
4. **NEW-C 落地时机**：先落承载页、继续挂「新 · 待对账」（编号后补），还是等图鉴对账出编号后与 NEW-T 一起转正落地？
5. **专区词卡反向链**：做（点词卡回词页）还是不做（保持词卡只朗读）？
6. **18MB 出货 App 的老构词模块**：本目标就此关闭（出货 App 另行立项再说）、长期搁置，还是现在就排期把专区与规律层移植过去？（注：旧 GOAL 文件的目标写的正是这件，若关闭建议同步销掉该目标文件，免得以后再被当成未办事项捡起来。）

> 附带一件无需拍板、随任何一案顺手办的小事：首页卡「547 条拆分」与专区副标题的镜像时代文案，无论选哪案都应修订（A 案已含）。
