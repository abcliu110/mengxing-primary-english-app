## 二、联动架构设计

### 1. 关系层：关系住哪、ID 缺口、链接索引怎么生成

**原则：事实关系住总表，派生关系由生成器算，全 App 只消费一份生成的链接索引。**

- **词的边以 words_master 为枢纽**（它已经是五源汇合处：morph/etym/phonics/vc 分仓都在词记录里）。不在词记录里手写新边；新增的边一律是「可由现有分仓机械导出」的派生边。
- **规律的边统一户口**：把 LAWDATA 仓的 rel 509 条（同族/前置/对照）登记进 laws_master，作为与裁定型 relations 并列的第二个关系仓（如 `relations_teaching`），仍由 gen_laws 生成下发。两套关系从此一张图：裁定型管「这条规律的来历与归属」，教学型管「学这条时该连到哪条」。
- **新建生成器 gen_links.py → LINKIDX**（一份生成的链接索引，随主文件内嵌，带 GENERATED 标记，进 check_all）：
  - 正向：word → {patterns[GP], laws[规律号], family_pages[pf], et_status（verified/pending/none）, dialogues[EXP id]}；
  - 反向：law → words[]（反转 VC 引用 + 家族页 + 规律例词）、pattern → words[]（已有成员表，直接引用）、dialogue → words[]（按 §2 的规则算）；
  - 规律图：合并两套 relations 后的邻接表。
  - 数据来源全部是现有总表字段，零新编内容；--check 与总表再生比对，计数与本备忘总账对不上即失败。
- **ID 缺口处置**：TEC-* 89 个悬空引用——建议在《数据源规范》里把 TEC 登记为「外部 id 空间」（技巧区自有户口，不入 laws_master），LINKIDX 对它们标 `external:TEC`，词页芯片落到技巧区对应页而不是正条；不许静默悬空。其余 id 空间（GP/pf/EXP/bank id）实测全对齐，无缺口。词源 join key 用 wordbank_key（31 个小写形已折叠的先例在案），13 个例外功能词与 195 未收词在索引里显式标 none。

### 2. 导航联动：三个枢纽面板

**（a）词页「这个词的全部联系」面板（新枢纽）**——位置：现行词页枢纽区（拼读分解块）之下、词源小结块的位置升级：
- 拼读：一行 GP 芯片（来自 LINKIDX 正向 patterns）→ 点进模式组页；
- 拆词：家族芯片（已有，保留）→ 家族页；
- 词源：把现内嵌小结升级为「状态徽 + 进专区」：已核/待核徽（et_status）+ 按钮 → ET 专区该词记录页（新增 ET.show(wordbank_key) 入口，词源区索引本就按词可查，只差一个对外开法）；
- 相关规律：规律芯片（已有第 12 位数据，改走 LINKIDX 以便含 TEC 分流）→ LAW.open / 专区规律页（指针路由现成）；
- 出现过的对话：对话芯片（LINKIDX dialogue 反向索引）→ 口语区场景页定位到该条；
- 同主题词：VC 主题标签同组词横滑（数据现成，纯渲染）。
面板每一行都是索引查表，无一行需要新内容。

**（b）规律页反向索引「这条规律管的词」**——位置：LAWDATA 规律页与专区规律页的例词区之后：词芯片云（LINKIDX law → words），显示总数 + 前 N 个 + 「全部」展开；点词进词页。效果：规律第一次能回答「学你有什么用、在哪些词上见你」。词根区规律页同理可用家族页词表（已在 morph 数据里）。

**（c）对话页回链**——位置：口语区场景页每条对话之下加「这条对话里的词」一行：LINKIDX dialogue → words 芯片（只列词库内词）→ 词页。规律回链**只做二阶且明示**：由这些词的规律芯片聚合出「相关规律」折叠区，标注「这些词涉及的规律」，不冒充「本课语法点」——对话数据里没有语法标注，硬标就是编造。场景问答（12 组）、拍手歌（8 首）同法处理（歌词行内词同理可算）。

**（d）对称补齐**：词源专区记录页加「看词页」按钮（ET 记录有 wordbank_key，现成）；家族页头加规律芯片行（pages.laws 字段 111 页现成数据，渲染即可）。

### 3. 学习联动：错题扩散、掌握传播、跨区推荐

**总原则：不新设存储，先把「题 key → 实体」的现成映射用起来；掌握度是算出来的视图，不是又一张表。**

- **错题沿图扩散（1 跳封顶）**：复习时答错一题 → 按 key 前缀解析实体（LQ/PB → 规律，GT → 站/模式，TA → 时态）→ 经 LINKIDX 取该实体的 1 跳邻居，生成「补强组」插进本轮队尾：同规律的其他题、该规律管的词里带题的词（经词 → 题的反查）、同模式的过关组题。每轮补强 ≤ 一组（如 5 题），且只扩散 1 跳——防滚雪球。规则全部来自已登记的边（同规律/同模式/同族），无新内容。**依赖**：复习池接口先把专区题纳池（已下单），扩散才覆盖全图。
- **掌握度沿边传播（计算层）**：新设一个纯函数层 mastery(entity)：词掌握 = 其名下池题状态聚合（+动词词并入 vb_srs 的同名字段）；模式掌握 = 该模式 GT 题 + 成员词掌握率；规律掌握 = 其 LQ/PB 题状态。全部从现有 5 个存储键 + LINKIDX 现算，不落新键（或只落一份缓存）。脊柱 DONESET 已是这个模式的雏形（从复习状态现算点亮），把它推广到全图即可。
- **跨区推荐（规则表驱动）**：推荐 = 沿教学型关系的定向遍历，明示理由：
  - 学完规律 X → 沿「前置」反边推「以 X 为前置」的下一条；沿「同族」推族内未学；沿「对照」推易混的那条（配原文对照点）；
  - 学完一个模式 → 推该模式成员词里未学的词页 + 其词源故事（已核的）；
  - 学完一个场景 → 推该场景词表里未学的词。
  推荐规则表是一份小配置（边类型 → 推荐话术模板），话术只引用实体名与关系名，不生成新知识内容。

### 4. 进度联动：喂总地图与家长学情

- **总地图（借鉴待办 A4）**：节点直接取实体：脊柱 167 站 + 十五区 + 规律族（按总表 part/分队聚合）+ 16 场景；点亮状态全部查 mastery 计算层。这样总地图不是新进度系统，而是同一份掌握度的地图视图。
- **家长学情**：现家长报告只有动词一处，改为消费 mastery 计算层：按区汇总（词学会了几个/规律碰过几条/模式点亮几站/场景读过几个），明细下钻到实体。数据源与孩子端完全一致，不另采。
- **依赖顺序**：LINKIDX（阶段 1）→ 关系户口合并（阶段 2）→ 池接口 + 扩散 + mastery（阶段 3，池接口已在做）→ 总地图/家长（阶段 4，与 A4 待办汇合）。每层只依赖前一层，不回头改数据。

## 四、一句话版

全 App 的知识其实只差一张索引：词、规律、模式、家族、词源、对话六类实体之间的边，数据里已经存了约 1.9 万条（拼读成员 11,375 + 词→规律 3,618 + 家族词表 3,060 + 词源 2,278 + 规律关系 556），缺的是把它们生成成一份全 App 共用的链接索引、把词页和规律页做成双向枢纽、再让复习与进度沿着这张图走——而不是再造任何新内容。
