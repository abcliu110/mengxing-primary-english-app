# 四种交互学习法集成分析备忘（2026-11-03）

基线：master e520387 的 `laws-prototype/mengxing-prototype-v1.html` 与 `model/` 总表，全文实测。结论先行：**四种方法里，现行 App 只有第一种（即时测验）是成建制的，第二种只有碎片，第三、第四种基本空白——但第三种（找错改错）的数据家底反而最厚，143 条现成病例三元组躺在数据层里只作展示。** 集成不需要每区各写一套：加一个共用交互引擎（每类一个组件），新题型走现行题源适配器入池，判答继续汇入 `RV.finalize → RV.answer + 错题本收录` 这一个出口，四类玩法自动获得 SRS 排程、错题本和闯关复用。

---

## 一、现行交互家底实测（归类总账）

### 1. 中央复习池（RV）：1,796 题，五种卡型

| 卡型 | 题量 | 实际操作 | 归四类 |
|---|---|---|---|
| choice | 683 | 点选项，即时判对错 + 展示解析 | 一·知识点小测（成建制） |
| reveal | 263 | 先自答 → 点揭晓 → 自评对错 | 一·小测（自评变体） |
| probe | 238 | 开放任务 + 量规（rubric），自评 | 一·小测（开放变体），沾三类边（任务里含 mis 病因陈述，但只读不操作） |
| gate | 594 | 看词朗读（TTS 范读）+ 自评 | 一·朗读测（自评） |
| build | 18 | 点词积木按序拼句（点选排序，**非拖拽**），拼对即判 | 二·组句（点选版，全池仅 18 题） |

判答统一出口：`finalize(card,it,ok)` → `RV.answer`（Leitner 五盒）+ `MXW.record`（错题本三分法收录）。这是全 App 唯一成建制的判答汇合点，**新题型只要接进这个出口，排程/错题/回链全自动到账**。

### 2. 闯关（#v-rush）

限时 15 秒/题 + combo 计分，题源只抽池中 choice 题（实测 225 道可抽）。归一类「闪电战」的近亲：限时是真限时，但题型是四选一而非正误判断，纯「对/错」二选一判断全 App 只有语法专题站的 AB 题零星存在。

### 3. 各区自有练习（不入池、判答不汇入 RV，各写各的）

| 区 | 自有交互 | 归类 |

### 4. 四类覆盖总账

- **一·即时测验：覆盖最广。** 池内 1,796 题全属此类（含变体），另有 GK/VB/VC/MZ/PK 五处区内成套或半套。缺的是纯正误「判断闪电战」形态。
- **二·动手操作：只有碎片。** 组句只有 build 点选版 18 题；点选只有介词照片一处；**真拖拽全站仅 2 处提及、连线配对零实现、点选划分句子成分零实现**。
- **三·找错改错：正式玩法为零。** 雏形两站（标点手术、分诊台）。但数据层躺着 143 条病例三元组只作展示（见第二节）——全 App 最大的「数据齐、玩法缺」落差。
- **四·改写类：为零。** 没有任何句式转换练习，尽管动词三形表（461 条）与疑问句规律群（QI-01–15）都在。

## 二、适配矩阵（内容 × 四种方法）

判定：◎适合 / ○勉强 / ✗不适合。数据就绪度：**A** = 现有数据可机械生成题目；**B** = 现有数据改造可得（挖空、切词、造错规则等需一道加工）；**C** = 需新编内容（估量级）。

| 内容族 | 一·即时测验 | 二·动手操作 | 三·找错改错 | 四·改写 |

| 拼读模式（174 模式 / 11,375 对） | ◎ A：词读这个音对不对（正误判断）、听音选词，pairs 机械生成 | ◎ A：连线 词↔音标；点圈目标字母组合（卡面切分现成） | ○ B：形近错读要靠规则造错例，无现成错读库 | ✗ |

| 连词（GR-38/46–50） | ◎ A：quiz 已入池 | ◎ **A：关联词填空是本行玩法——例句挖空连接词点选/拖入** | ○ B：连词病例少 | ○ B：两句合并成复句（组句式改写，例句对要备） |

| 介词（43 卷宗 / 8 家族） | ◎ A：178 题已入池 | ◎ A：填空选择已有 144；连线 介词↔义项；照片点选已有一处真实现 | ○ B：介词家族文件是讲解非病例，病例要另找 | ○ B：换介词改义对比 |
| 口语对话（144 对话 / 16 场景） | ○ B：听句选场景（scene_qa 12 组改造） | ○ B：拖拽组句（对话句切词打乱；跟读已是自有交互不重复造） | ○ B：usage_note 有易错提示但非病例结构 | ○ B：换人称复述（I↔you 转换，对话句现成） |
| 表达写作（W/E 规律） | ◎ A：quiz 在 LAWDATA 池内 | ○ B | ○ B：病例泛化可用 | ○ C：扩句/缩句需新编句子对（小学量级约 30–50 对起步，须过无编造纪律审核） |

**A 级格子合计 25 / 52。** 最亮的 5 个格子：

1. **词根 × 点选划分**：926 词的结构化词素就是点选划分的答案键，零加工。
2. **冠词 × 找错改错**：28 条真实语料病例带错因分类（冗余/缺失/误用），两段式玩法（先判错因、再选改法）直接成型。
3. **动词时态 × 找错改错**：31 条动词病例 + TA 题内 case_error，错因（时态漂移/与时间状语不匹配）现成。
4. **动词时态 × 改写**：461 条三形表 + 时态决策模型，四类里唯一 A 级的改写格。
5. **连词 × 关联词填空**：截图里点名的方法与内容的天然本行，例句挖空即可。

## 三、集成架构

### 1. 一个共用交互引擎，不许每区再写一套

现行已有 6 套判答实现（RV、GK、VB、VC renderQuiz、MZ 弹窗、PK），新玩法再各写一套只会继续碎片化。设计：

- **组件契约**：每个组件是一个纯渲染+判答函数 `mount(item, host, onDone)`，只管呈现与判对错，判完回传 `(ok, detail)`；后果（记 SRS、收错题、计分、结算）一律由宿主处理。宿主有三：复习池卡片、区内练习位、闯关。
- **组件清单（四类八件）**：一类 `judge`（正误判断，闪电战与小测共用底座，choice/reveal 是已有件不重写）；二类 `tapmark`（点选标注：划分/圈字母/点成分共用）、`dragorder`（拖拽组句，build 的点选版升级为可拖+可点双模）、`match`（连线配对，点两端连线，兼容触屏）、`fillpick`（点选/拖入填空：冠词、代词、连词共用）；三类 `spotfix`（两段式：点出错处 → 选错因 → 选改法，三段可裁剪）；四类 `rewrite`（给原句+转换指令，点选/拼装产出目标句判对错）。
- **标点医生**不单设组件：它是 `tapmark` 的一个模式（在去标点文本上点位置插入标点/点选大写），复用 GR-38 标点手术的内容口径。

### 2. 新题型如何入池、判答如何汇合

- 池题新增 kind：`judge / match / tapmark / dragorder / fillpick / spotfix / rewrite`，与现五 kind 并列；`renderCard` 按 kind 分发到引擎组件，判答仍走 `finalize` 一个出口——**Leitner 排程、错题本三分、回链按钮（data-law/zsrc 分发已有）全部自动复用，mxReviewV1 的 key 规则不变，老题 key 一个不动**。
- 题源走现行适配器模式加新源（srcCases 病例源、srcMatch 配对源、srcMorphTap 拆分源等），题面由新生成器 `tools/gen_interact.py` 从总表与病例文件机械生成、带 GENERATED 标记纳入 check_all（仿 extract_review_data 先例）。
- 区内练习位（规律页「练一练」、词页、家族页）嵌同一组件时，判答回传后由区内宿主调 `RV.answer(key, ok)` 直记（key 用与池内同一 key，保证区里练和池里练是同一户口）——顺带把 GK/VB 的孤岛判答往这个口子上引（本期不强制迁移其存量，只要求新增的走口子）。
- 闯关自动受益：judge 组件就位后，闯关加「判断闪电战」模式只是换抽题 kind + 换组件，计分/combo 壳不动。

### 3. 每类组件的数据结构（生成器输入）

| 组件 | item 结构 | 数据来源（机械生成路径） |
|---|---|---|
| judge | {句/说法， is_true, 解析} | LAWDATA cases 的 right（真）与 wrong（伪）成对；quiz reveal 题的 ans 与常见误答 |
| tapmark | {文本， 可点单元[]， 目标单元， 类别标签} | morph morphemes（词素边界）/ phonics 卡面切分（字母组合）/ 例句分词（成分版需标注，二期） |
| dragorder | {词块[]， answer_order} | build 既有结构扩容：LAWDATA 例句、对话句、TA 句例切词（切词后须过「答案唯一」校验：同句不含重复可互换词块才生成） |
| match | {左列[]， 右列[]， 配对键} | wordbank（词↔音标/义）、verb_forms_completion（原形↔三形）、morph pages（词素↔义）、prep senses（介词↔义项） |
| fillpick | {带空句， 候选[]， 答案， 解析} | 规律例句挖空目标词（冠词/代词/连词/介词），候选=同族混淆项（规律 exc/对照组现成） |
| spotfix | {病句， 错处跨度， 错因选项[]， 改法选项[]， 正句} | 三病例文件（81）+ LAWDATA cases（62），字段一一对应，零改写 |
| rewrite | {原句， 指令， 目标句， 可拼词块/选项} | 时态：TA 句例 + 三形表换形；疑问：QI 例句对；词形：词库造句面（B 级起步） |
| punct（tapmark 模式） | {去标点文本， 标点位点[]} | 规律/对话例句机械去标点（位点由原文标定，唯一性可验）+ GR-38 登记内容 |

### 4. 明确不适合硬套的内容（避免为集成而集成）

- **词源区**：考据链条没有「病句/改写」形态，除 B 级说法判断外四类皆不适合；硬套只会把词源学做成选择题。
- **口语跟读/ chant**：已有录音模仿这一自有交互，四类（纸笔题型谱系）套上去是降级。
- **白板动画、王牌速查、决策树、总地图**：呈现与导航形态，不是练习，不要为了「覆盖率」塞题。
- **家长角**：成人内容，不进孩子题池（现行 srcLAWDATA 已有此过滤，沿用）。
- **词页本身**：词页是枢纽与查阅面，只嵌一个「练这个词」的引擎入口（跳池内该词相关题），不在词页内再造题型。

## 四、分期路线

**一期（引擎骨架 + 找错类 + 判断闪电）**——先啃数据最齐、落差最大的：
引擎契约 + `spotfix` + `judge` 两组件；病例 143 条经学段/句长筛后由 gen_interact 生成入池（新 kind spotfix/judge）；闯关加判断闪电战模式。
验收：病例题在池内可答、答错进错题本、回链落原规律页；老 1,796 题 key 与构成逐项不变；check_all 全绿。

**二期（动手类三件）**：
`match`（四组配对数据入池）+ `tapmark`（拆词点选 926、圈字母组合）+ `fillpick`（冠词/代词/连词例句挖空入池）。
验收：三组件各至少两个内容族在跑；点选划分的答案键与 morph 总表逐词对账；挖空题候选不含正确答案同形异义的歧义项（生成器断言）。

**三期（组句升级 + 标点 + 改写起步）**：
build 升级 `dragorder` 并扩容（例句切词生成，过唯一性校验）；标点医生（tapmark 模式，例句去标点生成）；`rewrite` 先上时态转换（A 级格），QI 疑问转换（B 级）跟进。
验收：拖拽与点选双模在真机触屏可用（390px 复测——注意本机 headless 限制，需 Stewart 真机或替代验证路径）；改写题目标句与三形表逐项对账。

**四期（长尾，按需立项）**：
点选句子成分（需例句结构标注的小批量新数据，C 级，按规律逐条标，不批量造）、表达写作扩句缩句（C 级句子对 30–50 起步，逐条过审）、口语拖拽组句与换人称复述（B 级）。

一句话版：**一期把 143 条病例变成能玩的找错题、顺手给闯关补上判断闪电战；二期补齐动手三件（连线/点选划分/填空）吃掉 25 个 A 级格子里的大头；三期上拖拽组句、标点医生和时态改写；成分点选与写作改写是 C 级长尾，不批量造数据。**
