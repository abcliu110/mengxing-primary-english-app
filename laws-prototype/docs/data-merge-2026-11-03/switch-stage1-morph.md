## 三、写回实验（临时副本）

1. **原样写回**：对两文件的临时副本跑 `--write`，两文件均报告「两段均与现行逐字节相同，文件未改动」；`diff` 写回副本 vs 原文件 **0 行**，`cmp` 逐字节相同（全文零差异：主文件 18,658,706 字节、原型 694,831 字节，写回前后不变）。
2. **扰动修复实验**（证明写回不是空转）：在 morphology 副本上人为注入三处破坏——DATA 内一处标题改字、一处序列化加空格（`"groups": [ {`）、LAWREG 内一处正文改字。`--check` 正确报出内容不一致并定位到 `$.groups[0].title`、`$.V-33.kid`（退出码 1）；`--write` 后文件由 694,851 字节恢复为 694,831 字节，`cmp` 与原文件**逐字节相同**，`--check` 复跑退出码 0。
3. **深比复核**：用 check_morph_sync.py 的抽取/深比逻辑对三份副本（写回主文件副本、写回原型副本、修复后原型副本）与事实源比对，DATA/LAWREG 共 6 项全 PASS。

## 四、序列化格式要点（反推自现行字面量，后续波次可直接复用）

1. **紧凑 JSON**：分隔符 `,` 与 `:`，无任何空白、无缩进、无尾随换行（字面量后紧跟 `;`）。
2. **双引号**：键与字符串一律双引号（JS 对象字面量裸键写法不存在，现行即纯 JSON 文本，可被 JSON.parse 直接解析）。
3. **非 ASCII 原样**：中文、音标（ɪ/ə 等）、emoji、序号圈号（①）一律 UTF-8 原字输出，不用 `\uXXXX` 转义。
4. **零转义现况**：现行两段字面量内**不含任何反斜杠**（无 `\"`、无 `\n`、无 `\/`），正文中的引号一律用中文引号『』「」避开 ASCII 双引号——再生时无需特殊转义策略，标准 JSON 转义（`"`、`\`、控制字符）即可完全覆盖未来新增内容。
5. **数值**：全量扫描无浮点数（全为整数），无 JS/Python 数值格式分歧风险。
6. **键序**：按事实源文件中的存储顺序输出即与现行一致；全量扫描**无整数型键名**（如 "0"、"12"），不存在 JS 对象整数键前置重排与存储序分歧的隐患。若将来新增整数型键，须先复核本条。
7. **安全**：字面量内不含 `</script>` 子串、不含 U+2028/U+2029，直接嵌回 `<script>` 安全。

再生实现即一行：`json.dumps(obj, ensure_ascii=False, separators=(",", ":"))`（Python 标准库）。

## 五、写回安全边界（锚点定位方法）

- 定位锚：`const DATA = ` 与 `const LAWREG = `；DATA 在两文件中另有同名干扰，故附加起始过滤 `{"groups"`。过滤后两文件两段**各命中恰好 1 处**（主文件 DATA 始于字符偏移 12,837,723、LAWREG 始于 13,338,640）；命中数 ≠ 1 时生成器拒绝操作并报错。
- 跨度确定：自锚后首个 `{` 起做字符串/注释感知的定界扫描（与 check_morph_sync.py 同一逻辑），止于配平的 `}`，替换范围仅该跨度；跨度外字节（包括紧随的 `;` 与全部其余内容）原样保留。两段替换按偏移降序执行，互不干扰。
- 文件 IO 按字节读、UTF-8 解码、替换后 UTF-8 编码写回；两文件无 CR 字符，不存在换行符翻译风险。
- 幂等：对已一致的文件跑 `--write` 为无操作（不写盘）。

## 六、与校验门的衔接

- `gen_morph.py --check`（本生成器自带）：比对的是**文本**——事实源再生文本 vs 现行字面量文本，三级结论（逐字节一致 / 深相等但序列化不同并给出首个差异位置 / 内容不一致并给出差异路径）。
- `check_morph_sync.py`（Wave 2 既有）：比对的是**语义**——node 求值后三方两两深比。
- 两者互补：落盘流程建议固定为 `--write` 两个文件后先跑 gen 的 `--check`（应全 byte），再跑 check_morph_sync.py（应全 PASS），双绿才算切换完成。
