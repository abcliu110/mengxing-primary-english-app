# 萌星英语 · 规律版 —— 设计文档（数据与系统设计）

> 配套文档：《需求文档 REQUIREMENTS》（产品需求口径）、`model/README.md`（数据总账）、`model/WORDBANK.md`（词库规则）、`model/WORDBANK_MODEL.md`（词库建模评审稿）。
> 本文只写**设计口径**：数据怎么组织、怎么转化、怎么生成、怎么校验。不写产品需求（需求以需求文档为准），不写逐条内容（内容在模型文件里）。
> 状态：草案 v1（2026-11-01）。本文自身也走文档制度：变更记入总账，结构性修改过评审再定版。

## 1. 总体架构

### 1.1 四层与单向依赖

系统分四层，依赖只许自上而下（上层引用下层，下层永不反向引用上层）：

```
┌─────────────────────────────────────────────────────────┐
│  视图生成层  单文件 HTML（动画 / 卡片 / 测验 / 复习 / 家长角） │
│              全部由模型渲染，文案零副本，进度存本地          │
└──────────────────────▲──────────────────────────────────┘
                       │ 渲染时读取（构建期内联，见 §1.2）
┌──────────────────────┴──────────────────────────────────┐
│  规律模型层  规律条目 / 探针条目 / 技巧条目（typed 模型）     │
│              条目的例词、例句用词只引词库 id               │
└──────────────────────▲──────────────────────────────────┘
                       │ law_refs / 例词 id 引用
┌──────────────────────┴──────────────────────────────────┐
│  词库层（第〇层 · 根） wordbank.json（1,567 条 + 补入）      │
│              词的全部事实只存一份；不依赖任何上层           │
└─────────────────────────────────────────────────────────┘

   校验层（横切）：对词库层与规律模型层做全部硬校验；
   校验不过关 → 阻断生成，视图生成层不产出新构建。
```

要点：

- **词库是根**：删一条规律，词库不受影响；删改一个词条，全部引用它的条目经校验层立刻显形（悬空引用报错）。
- **模型是唯一事实源**：视图层不持有任何文案副本。改正文 = 改模型条目 → 重新生成 → 全部视图（动画台词、要点卡、测验、复习卡）同步变化。
- **校验层是闸门，不是报表**：任何一条硬校验失败，本次构建整体作废，不存在「带病上线」。

### 1.2 单文件离线交付如何由模型生成

交付形态是单个 HTML（双击打开、离线、无账号、无服务器）。生成管线：

1. **构建期**（开发机上跑）：校验层全量校验 → 生成器读词库 + 模型 → 把所需数据以 JSON 形式内联进 HTML 模板 → 动画场景由 wb5 引擎按场景规格在运行时渲染（场景规格来自模型，台词与用词在构建期已校验）。
2. **运行期**（用户机器）：HTML 内联数据 + wb5 引擎自包含运行；学习进度（错题病因归档、复习队列状态）存浏览器本地存储，不回传、不依赖网络。
3. **体积控制**：内联数据按区裁剪——只内联已入模且状态为「定版/上线」的条目；候选区条目不进包。体积上限与拆分策略是未决问题（见 §8-Q2）。

## 2. 词库层

词库的建模结论见 `WORDBANK_MODEL.md`（评审稿），本文不复制，只规定**本设计的使用方式**：

### 2.1 使用方式

- 内容侧（规律条目、探针、技巧、场景规格）引用词，只许写词库 `id` 或在校验口径下可归一命中的词形；展示时的音标、释义、拼法一律从词库按 id 渲染。
- 词库字段口径以 `WORDBANK.md` 字段表为准。本文出现的挂接字段名与词库严格一致：`gpc_patterns` / `morphemes` / `law_refs`，另有归一匹配用的 `aliases` 与 `verb_form_of`、谓词推导用的 `pos_tags` / `sight_type` / `has_polysemy` / `is_function_word` / `theme_macro` / `theme_sub`。

### 2.2 挂接字段回填流程

三个挂接字段建库时留空，在入模流水线（§4）中按波次回填：

| 字段 | 回填时机 | 回填依据 | 回填后校验 |
|---|---|---|---|
| `gpc_patterns` | 拼读区波次 | 该词拼写命中的 GPC 模式清单（S/SR 条目定义模式全集） | 每个模式 id 必须在 S/SR 条目中存在；模式的词表 = 词库中挂该模式的全部词（与菜单完整性检查共用同一推导，见 §5） |
| `morphemes` | 词汇解码区波次 | 词根词缀拆分（前缀/词根/后缀 + 透明度评级） | 拆分所用词素必须在 V 组词素清单中登记；不可拆的词显式标 `null`（=已判不可拆），与「未回填」区分 |
| `law_refs` | 各区波次滚动回填 | 该词作为例词/成员出现的规律条目编号 | 双向闭包：条目引词 id ⇔ 词条 `law_refs` 含该条目（见 §6 挂接闭包检查） |

回填是**逐词全库**进行（菜单全量呈现的前置条件），不是只填被例词用到的词：拼读波次要给全库每个词判定 gpc_patterns（命不中任何模式的词也要显式判空），词汇波次同理判定 morphemes。

## 3. 规律模型层（核心）

模型层有三类条目：**规律条目**（主体，428 条清单的入模产物）、**探针条目**、**技巧条目**。三类共用版本与状态字段口径。

### 3.1 规律条目 schema

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✓ | 清单编号沿用（如 `S-36`、`V-40`、`GR-33`、`SR-01`），全局唯一，永不复用 |
| `zone` | enum | ✓ | 区属：拼读 / 词汇解码 / 语法 / 小系统 / 表达写作 / 支撑层（家长角与教师层条目） |
| `group` | string | ✓ | 清单组别（S / SR / V / GR / TA / CO / QI / P / C / PR / PB / E / W / NE / …），与图鉴、清单对账用 |
| `headline` | string | ✓ | 标题句（机制级一句话，成人可读口径） |
| `headline_kid` | string | ✓ | 儿童版标题句（孩子能复述；学术词不进此字段） |
| `claim` | object | ✓ | 核心断言，见 §3.2 分型 |
| `mechanism` | object | ✓ | 机制讲解结构，见 §3.3 |
| `examples` | array | ✓ | 分级例证，见 §3.4；例词只引词库 id |
| `error_cases` | array | ✓ | 病句医院病例 ≥1，见 §3.5 |
| `relatives` | array | | 亲戚网：与本条相关的条目 id + 关系类型（同族 / 对照 / 前置 / 易混） |
| `scene_spec` | object | MVP 区必填 | 动画场景规格：事实表（对象、类别、状态变化、守恒）、节拍引用 claim、台词行归属条目（文案存模型，场景只引用） |
| `quiz` | array | ✓ | 检索练习题：题干、选项/作答、**答错回机制提示**（指向 `mechanism` 的具体小节，不给答案） |
| `probes` | array | ✓ | 误解探针引用 ≥1（探针条目 id，见 §3.6） |
| `prereq` | array | | 前置条目 id（区内学习顺序由 `prereq` + `order` 推导，不按学段切分） |
| `order` | int | ✓ | 区内默认顺序序号 |
| `pain_points` | array | | 命中的痛点入口（记不住 / 听不懂 / 说不出 / 写不长 / 读不快 / 错不完），供痛点入口索引生成 |
| `adult` | object | ✓ | 成人层，见 §3.7 |
| `config_gates` | object | | 配置开关门控（如弱读产出档位 A、POA 档位 B 影响的呈现与练习要求；开关只改呈现，不改数据本体） |
| `status` | enum | ✓ | 候选 / 入模中 / 已入模 / 定版；未达「已入模」齐备标准的条目留候选区不上屏 |
| `version` | string | ✓ | 条目版本号；`changelog` 记录每次改动（日期、改了什么、依据） |

### 3.2 claim 分型（硬门槛，分型不对不许入模）

`claim` 对象字段：`type`（分型）、`statement`（断言正文）、`evidence`（证据：专家 + 著作 + 可核链接，标注接触等级）、`scope`（适用范围）。

| type | 含义 | 必填项（缺一校验不过） |
|---|---|---|
| `rule` | 可判定对错的规则 | evidence ≥1 且例证支持 ≥2 条（`examples` 中标注 `supports` 本 claim 的 ≥2 级） |
| `tendency` | 倾向/规律性（有例外才成立） | `scope` 必填；`exceptions` ≥1（已知例外清单，每条例外自带例词 id）；statement 禁绝对化措辞 |
| `mnemonic` | 口诀/助记（只是记法，不是事实） | `linked_claim` 必填且可解析（它帮记的那条真 claim）；呈现时必须标注「可以想成」；statement 禁绝对化措辞 |
| `etymology` | 词源叙事 | `source` 必填（来源语、原义、出处）；叙事与事实分开标注 |

专家分歧不许在条目内悄悄裁决：分歧写入 `adult.disputes`（见 §3.7），claim 只写当前呈现口径并注明「有分歧，见成人层」。

### 3.3 mechanism 机制讲解结构

`mechanism` = 有序小节数组，每节：`beat`（小节名）、`text_kid`（儿童面讲解：从具体场景出发）、`text_adult`（教师/家长口径，可用学术词）、`visual`（示意规格：画什么机制动作，引用元素/道具或图式类型，不画装饰）、`anchors`（本节用到的例词 id，可为空）。六步闭环中「动画讲机制」与「一屏一总结」都由本字段渲染：总结屏 = `headline_kid` + 首节 `visual` + 亲戚网/菜单类附件（由 §5 谓词推导）。

### 3.4 examples 分级例证

每条 `examples[]`：`level`（级次，自 1 起）、`word_ids`（例词，**只许词库 id**，≥1）、`sentence`（例句；句中每个实词须可归一命中词库，校验层逐词查）、`scene_note`（场景说明：须为中国孩子真实生活/教材场景）、`supports`（支持的 claim 或小节引用）。每条规律 ≥2 级、每级 ≥2 例（产品规格）；例证不得自带词库外新词——需要新词先走补词流程（WORDBANK 规则 2）。

### 3.5 error_cases 病句医院病例

每条 `error_cases[]`：`wrong`（错句）、`right`（正句或正解）、`error_type`（错因分类，与复习区病因归档共用同一分类表）、`source_type`（来源类型，必填：真实语料错型 / 教学文献登记错型 / 条目成人层登记的事故例；**不许标注为真实错例的自编句**）、`diagnosis`（为什么错，回指 mechanism 小节）。错题在复习区的归档键 = `error_type`，不按题号。

### 3.6 探针条目 schema（要点）

探针独立成条，规律条目以 id 引用（引用粒度是未决问题，见 §8-Q3）。字段：`id`（如 `PRB-S36-1`)、`for_law`（所属规律条目 id)、`predicted_misreading`（预判误读，孩子视角一句话）、`source_of_prediction`（依据：条目边界 / 难点地图 / 技巧误用警告，须可回指）、`task`（分水岭探针题：按误读答必错、按机制答才对）、`rubric`（三态量规：中招 / 中间态 / 过关各自的判据）、`remedy`（中招后回补到所属规律六步闭环的哪一步、哪个机制小节）、`word_ids`（探针题用词，只引词库 id；题中故意错拼登记为错形展示，不入词库、不算库外词）。现状：探针库 v1 共 40 个（8 组 × 5），入模时逐条转此 schema。

### 3.7 adult 成人层

`adult`:`sources`（出处清单：专家/机构 + 著作/篇目 + 链接 + 接触等级）、`boundary`（边界与不适用情形）、`disputes`（专家分歧，如实登记，不裁决）、`evidence_grade`（证据等级自评）、`pending`（待核项清单，可为空但字段保留）。家长角即本字段的聚合视图。

### 3.8 技巧条目 schema（要点）

技巧是「招」不是「理」，独立成条供闭环各步调用：`id`（TEC-* 沿用技巧目录编号）、`pain_point`（主治痛点，六选一或多选）、`name`、`when`（适用时机）、`steps`（操作步）、`self_check`（自检标准）、`misuse_warning`（误用警告）、`linked_laws`（服务的规律条目 id，可多）、`order_hint`（前置/顺序提示，代替已废止的学段字段）、`evidence_note`（依据与证据等级）。现状：137 条候选，二期定版（去重 + 听不懂补挖）后转此 schema。

## 4. 入模流水线

### 4.1 转化步骤（每条规律固定八步）

1. **拆条**：从清单 v6 散文中拆出标题句、机制、支撑、边界、分歧，落到 schema 字段；拆不出机制的条目停单回报，不硬凑。
2. **定型**：给 claim 分型并补齐该型必填项（证据/范围/例外/linked_claim/source）；证据只能用清单里已核的出处，不新编。
3. **儿童面转化**：写 `headline_kid` 与 `mechanism.text_kid`（接地气口径：具体场景出发，学术词只进成人层）。
4. **例证落词**：例词逐词对词库——命中记 id；未命中走补词流程（核查后先入词库）或换例词；例句逐词归一校验。
5. **病例与探针**：配 ≥1 真实错型病例（注明来源类型）+ 引用 ≥1 探针（缺探针的新条目当场补写探针并登记进探针库）。
6. **挂接回填**：回填涉词的 `gpc_patterns` / `morphemes`（按本区波次职责，见 §2.2）与双向 `law_refs`。
7. **校验**：过 §6 全部硬校验；不过回炉，不降级放行。
8. **登记**：模型文件落盘 + 该组建模文档更新 + 总账登记（规模、状态、变更一笔）。

### 4.2 波次顺序（按区推进）

| 波次 | 范围 | 说明 |
|---|---|---|
| W0 | 词库补全 | 真缺词 + 边缘词共 400 词核查补入（进行中）；补后覆盖复查归零才开 W1 |
| W1 | 拼读区（S 43 + SR 9) | 内容最新最完整；同时完成全库 `gpc_patterns` 回填与 sight_type 判定 |
| W2 | 词汇解码区（V 45 + CO-17 等） | 完成全库 `morphemes` 回填；词族成批处理 |
| W3 | 语法区（GR 45 + TA 18 + CO 17 + QI 15) | 总纲三条置顶先行 |
| W4 | 小系统区（P 19 + PB 13 + C 20 + PR 11) | 介词花园为既有骨架升级 |
| W5 | 表达写作区（E 15 + W 15 + NE 29) | — |
| W6 | 支撑层（TM / LS / YL / CB / CG / VB / WA) | 只入成人层/教师层呈现，不进孩子菜单 |
| W7 | 探针库、技巧库定版入模 | 探针随各波滚动转化，本波收口；技巧二期定版后入模 |

### 4.3 每波产出物（三件套，缺一不算完）

1. **模型文件**：本波条目（`model/` 下按组文件，格式见 §8-Q1);
2. **该组建模文档**：本组的口径决定（如菜单谓词细化、分型争议处理）随文记录；
3. **总账登记**：`model/README.md` 更新规模、状态与变更日志。

## 5. 菜单生成与全量呈现

### 5.1 词集谓词（菜单词集 = 谓词推导集，不手工挑词）

| 区/菜单 | 谓词（词库字段） | 推导结果 |
|---|---|---|
| 拼读区 · 各拼法菜单 | `gpc_patterns` 含该模式 id | 该模式的全部词（菜单全量） |
| 拼读区 · 不规则词表 | `sight_type == irregular` | 全部不规则词 |
| 词汇解码区 · 词族/变身机 | `morphemes` 含该词素 | 该词素家族全部词 |
| 词汇解码区 · 多义 | `has_polysemy == true` | 全部多义标记词（标记覆盖补齐是 W2 的活） |
| 语法区 · 动词类单元 | `pos_tags` 含 `v.`（含情态单列） | 全部动词 |
| 语法/小系统 · 名词类单元 | `pos_tags` 含 `n.` | 全部名词（可数性再按条目内分类字段细分） |
| 小系统区 · 介词/代词/冠词 | `pos_tags` 含 `prep.` / `pron.` / `art.`·`det.` | 各全量 |
| 小系统区 · 功能词 | `is_function_word == true` | 全部功能词 |
| 表达写作区 | `theme_macro` / `theme_sub` 主题谓词 + `pos_tags` 含 `phr.` | 主题词全量 + 短语条目 |

谓词口径的细化（如多义词标记补齐到什么程度、主题谓词的边界）写入各区建模文档评审定版；谓词一旦定版，菜单词集由生成器自动推导，任何人工增删都必须改谓词或改词库标记，不许在视图层藏词。

### 5.2 单元列表生成

各区单元列表 = 该区 `status ≥ 已入模` 的规律条目按 `order` 排序渲染；单元内的例词展示、拼法菜单、词族名单全部按 §5.1 谓词现推，不存静态名单。复习区不生成新内容：错题按 `error_type` 从各条目 `error_cases` 与练习作答记录聚合，间隔队列由病因与作答历史在运行期计算。

## 6. 校验层

校验器在每次构建前全量运行，任一硬校验失败即阻断生成。清单如下（「处置」列为不过关时的唯一合法处理）：

| # | 校验 | 内容 | 不过关处置 |
|---|---|---|---|
| V1 | schema 校验 | 全部条目字段齐全、类型与枚举合法、id 全局唯一 | 阻断；回该条目补齐，不许默认值蒙混 |
| V2 | claim 分型硬门槛 | rule 例证支持 ≥2;tendency 有 scope 且例外 ≥1;mnemonic 的 linked_claim 可解析；etymology 有 source | 阻断；回炉定型（§4.1 步 2)，不许改型降格（如把 tendency 标成 rule）绕行 |
| V3 | 例词覆盖检查 | 全部条目、探针、技巧、场景台词的用词逐词比对词库（word/aliases 命中或 verb_form_of 归一；错形展示登记项除外） | 阻断；输出库外词清单，逐词补入词库（走核查）或换例词，清单非空不放行 |
| V4 | 菜单完整性检查 | 每区菜单词集与 §5.1 谓词推导集逐词比对 | 阻断；查明是标记漏回填还是谓词口径问题，修在词库/谓词侧，不许视图层补名 |
| V5 | 挂接闭包检查 | 条目引词 id 全部可解析；词条 law_refs 与条目引用双向一致；gpc_patterns/morphemes 所引模式与词素在对应清单中存在 | 阻断；修引用或补登记，不许删引用消警 |
| V6 | 绝对化措辞扫描 | claim.statement 及儿童面字段禁含红线词（绝对化表述清单：如「一律 / 永远 / 从来都」及物理边界类误表述），tendency/mnemonic 从严 | 阻断；改写为带范围/例外的表述，或降型重定 |
| V7 | 呈现完整性 | 每条已入模条目六步闭环素材齐备（病例 ≥1、例证 ≥2 级、探针 ≥1、测验含回机制提示、成人层出处可核） | 条目退回候选区，不上屏；不阻断其他条目构建 |

校验器输出固定附在每波交付报告中（与总账登记同批），不许只报「通过」不报清单。

另有一项由校验层支撑的维护能力：**变更影响范围列出**——凭 `law_refs` 双向索引与条目间引用（relatives / prereq / probes)，任一词条或条目变更时，工具须能列出全部受影响的条目与视图，供改后逐一复核（数据可维护性要求）。场景级交付检查（动画自动检查 0 失败、事实表完备）属场景规格验收，在 `scene_spec` 落地时执行，不在本模型校验清单内，但同为上线门槛（见需求文档验收标准）。

## 7. 文档制度落地

- **谁写**：执行入模/改数据的当事方（人或 AI 代理）写；主会话复核后落盘。子代理产出的数据变更，由主会话在提交前同步文档，未同步不提交。
- **写什么**：每次数据变更固定三处落字——(1) 数据本体文件的 `changelog`/版本字段；(2) 该数据集专属文档的变更记录（日期、改了什么、依据）;(3) 总账 `model/README.md` 的登记表（规模/状态）与变更日志各一笔。
- **评审状态流转**：`草案 → 评审中 → 定版`。交评审时在总账标注评审对象与日期；评审意见逐条回记专属文档（采纳/不采纳及理由）；结构性 schema 变更必须过评审才许定版，内容条目的小修走 changelog 即可。
- **随时可改的边界**：文档与数据随时可改，但已定版的结构（字段、谓词口径）改动须重走评审流转并在总账留痕，不许静默改口径。

## 8. 未决设计问题（真问题，未定版）

| # | 问题 | 候选 | 当前倾向 |
|---|---|---|---|
| Q1 | 模型文件格式：JSON vs YAML | (a) JSON：与词库同格式、程序友好，但长文本（机制讲解）可读性差；(b) YAML：旧建模线已验证的可读性与分型校验经验，长文友好，但需解析器且与词库双格式 | 倾向 YAML（条目长文多、人工评审频繁），词库保留 JSON；待评审确认 |

| Q4 | `has_polysemy` 标记覆盖补齐的标准 | (a) 只补规律条目实际展开义项网络的词；(b) 按学习词典义项数阈值全库普查标记 | 倾向 (a)：标记服务于菜单呈现，普查成本高且口径无权威源；W2 建模文档中定版 |
