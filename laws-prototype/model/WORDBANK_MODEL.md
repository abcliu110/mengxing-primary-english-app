# 词库建模说明（评审稿）

> 用途：供外部评审（其他 AI / 专家）审查本词库的数据建模是否合理。评审对象是**建模决策**，不是词条内容对错（词条内容已经过一轮逐条裁定核查）。文末列有明确的评审问题清单。
> 对象产品：儿童英语学习 App（新产品，独立于旧版）。词库文件：`wordbank.json`（与本文同目录）。建库日期：2026-11-01。

## 1. 定位与首要原则

词库是整个 App 数据模型的**第〇层（根）**，产品负责人的原话裁定：「先有词库，然后其他的必须依赖词库。」

由此导出四条建模约束：

1. **一词一源**：同一个词的音标、释义、拼法等事实只在词库存一份；规律条目、练习、动画台词等内容层只引用词条 `id`，不复制词条事实。
2. **例词必有出处**：内容层出现的任何英语词必须能在词库中命中（按 `word`、`aliases` 或经 `verb_form_of` 归一）。内容需要库外新词时，先补词入（经核查）再引用。
3. **单向依赖**：规律层通过挂接字段回连词库；词库不依赖任何规律条目（删一条规律，词库不受影响）。
4. **有意排除**：例句、搭配、讲解**不进词库**——它们属于内容层，只引词条编号。词库只存「词本身的事实」。

## 2. 数据来源与规模

- 来源：由旧版 App 已核查的词表（VOCAB_DB）机械导出，未在导出过程中改写词条事实；新产品独立持有本文件。
- 总量：**1,567 条**。
  - 教材/课标条目 1,065：按册别分布 G1 72 / G2 85 / G3 189 / G4 214 / G5 300 / G6 205（含 11 条 Dolch 别名条目）；
  - 主题扩展条目 500（id 前缀 `V6_`，按学校、身体、食物等子主题组织）；
  - 多义专条 2。
- 主题分布（课标三大主题）：人与自我 597 / 人与社会 300 / 人与自然 170 / 扩展库 500。
- 展示口径：1,567 为数据条数；其中 56 条是动词变形条目（见 §4.3），词表界面按产品规则只显示原形，实际展示 1,511 条。

## 3. 词条结构（字段表）

每条为一个 JSON 对象，共 21 个字段（`aliases`、`pos_tags` 为建库后整理时新增，见 §4）。

| 字段 | 类型 | 说明 | 填充率 |
|---|---|---|---|
| `id` | string | 稳定编号，如 `G3_K01`、`V6_学校_54`；内容层引用只用 id | 100%，唯一 |
| `word` | string | 词形；复合词头保留原样，如 `be / am / is / are` | 100%，唯一（大小写不敏感口径下无重复） |
| `aliases` | string[] | 复合词头的成员别名（`be`、`am`…），使每个成员可独立命中 | 14 条复合词头有值，其余缺省 |
| `phonetic` | string | 音标（源库转写风格，宽式） | 100% |
| `syllables` | string | 音节划分 | 100% |
| `pos` | string | 词性原文，如 `n.`、`v./n.`（兼类连写，保留源貌） | 100% |
| `pos_tags` | string[] | 由 `pos` 机械拆出的结构化词性标签 | 100% |
| `meaning` | string | 中文释义（单释义；多义词只给主导义，义项展开在规律层） | 100% |
| `emoji` | string | 图示符号（呈现层用） | 100% |
| `freq_rank` | int | 词频排名（继承自源库，语料口径未随库文档化——已知缺口，见 §6） | 100% |
| `theme_macro` / `theme_sub` | string | 课标大主题 / 子主题 | 100% |
| `sight_type` | string | 可解码性：`decodable` 726 / `irregular` 19 / 未标 822 | 部分 |
| `is_function_word` | bool | 功能词标记，57 条 | — |
| `has_polysemy` | bool | 多义标记，17 条 | — |
| `dolch` | string\|null | Dolch 分级（pre-primer / primer / grade1–3），202 条有值 | 部分 |
| `kebiao_level` | string\|null | 课标级别（现仅「二级」60 条） | 部分 |
| `verb_form_of` | string\|null | 变形条目指回原形词，如 `was → be` | 56 条有值 |
| `gpc_patterns` | string[] | **挂接字段**：该词命中的拼读（GPC）模式，入模时回填 | 建库时为空 |
| `morphemes` | object\|null | **挂接字段**：词根词缀拆分，入模时回填 | 建库时为空 |
| `law_refs` | string[] | **挂接字段**：该词所属规律条目编号，入模时回填 | 建库时为空 |

词性标签口径（按 `pos_tags` 计，一词兼类计多次）：名词 953、动词 276、形容词 234、副词 96、代词 54、数词 43、介词 34、限定词 29、连词 10、情态动词 7、短语 5、感叹词 4、冠词 2；兼类词 175 条。

## 4. 三个关键建模决策（请重点评审）

### 4.1 复合词头不拆条，用别名解决可查性
源库有 14 条复合词头（`a / an`、代词组 `I / me / my / mine`、`be / am / is / are`、疑问词组等），它们在教材里就是成组教的。建模选择：**不拆成独立条目**，保留词头原样，另给每条加 `aliases` 列全成员。内容层查 `a`、`be`、`who` 均可命中其词头条目。代价：别名与词头的释义共享（`my` 与 `mine` 共用一条释义），细粒度区分留给规律层。

### 4.2 词性双轨：原文 `pos` + 结构化 `pos_tags`
源库词性是给人看的字符串（40 种写法，兼类连写）。建模选择：原文保留不改，另机械拆出 `pos_tags` 数组供程序按词性取词（如可数性规律只取名词、三单规律只取动词）。拆分规则仅按 `/` 切分，无人工判断；`modal v.`、`phr.` 等作为独立标签保留。

### 4.3 动词变形独立成条，用 `verb_form_of` 回指
was / went / studies 等 56 个变形不折叠进原形条目，而是各自成条并以 `verb_form_of` 指回原形。理由：变形本身是孩子要认的词形（Dolch 词表里就有），且拼读层要单独处理其可解码性。展示层再按产品规则隐藏。已校验：56 条回指全部可达（经 `aliases` 归一后断裂为 0；建库初检曾发现 was/were/been 因原形是复合词头而断链，由 §4.1 的别名机制修复）。

## 5. 完整性校验（建库时已跑）

- `id` 无重复；`word` 无重复（大小写不敏感）；
- 核心字段（phonetic / pos / meaning / syllables / freq_rank）空缺为 0；
- `verb_form_of` 回指闭包完整（0 断裂）；
- 计划中（入模阶段）的持续校验：内容层例词覆盖检查——扫描全部内容条目用词比对词库，输出库外词清单，非空不过关。首轮存量审计进行中。

## 6. 已知缺口（不回避）

1. `freq_rank` 的语料来源与口径未文档化（继承自源库），无法据此做严格的频率论证。
2. `phonetic` 为源库宽式转写，未区分英式/美式双标；个别词的转写风格一致性未经独立复核。
3. `meaning` 单释义：多义词的义项网络不在词库展开（有意排除，见 §1.4），但 `has_polysemy` 只标了 17 条，覆盖率存疑。
4. `sight_type` 未标 822 条——多为非拼读相关条目，但「未标」与「不适用」未作区分。
5. `kebiao_level` 仅 60 条有值，分级维度基本空缺。
6. 挂接三字段（gpc_patterns / morphemes / law_refs）尚为空壳，词库与规律层的实际耦合度未经真实入模检验。

## 7. 请评审回答的问题

1. 词库作「根」的单向依赖与「例句/搭配不进词库」的边界划分是否合理？哪些现在排除的维度其实应进词库（如词族关系、常见搭配、易混词对）？
2. 复合词头不拆条 + 别名的方案，对儿童查词与程序取词是否够用？代词组共用释义的风险有多大？
3. 动词变形独立成条 vs 折叠为原形条目的子结构，哪种更利于拼读与语法两侧调用？
4. `pos` 原文与 `pos_tags` 双轨是否冗余？标签集（13 类）对小学英语是否粒度合适？
5. 单释义 + 规律层展开多义的方案，在孩子实际查词场景下会不会造成「查到的义对不上课文的义」？
6. 字段缺口中（§6），哪几项必须在入模前补齐，哪些可以后置？
7. 存储形态：单 JSON 文件（现 731 KB）在单文件离线 App 的约束下是否合适，还是应拆分/换格式？
