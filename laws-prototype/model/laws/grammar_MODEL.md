分型硬门槛已逐条自检：rule 均有 evidence ≥1 且 examples 中 supports=claim 的例证 ≥2 级；tendency 均有 scope 且 exceptions ≥1，statement 经绝对化措辞扫描（一律/永远/从来都等红线词 0 命中——初检命中 GR-31、GR-39 各一处「一律」，已按清单原意改写为带范围表述后归零）；etymology 均有 source。

### 1.2 例证口径

- 每条 2 级 × 2 例 = 4 例，共 180 例；例句场景一律取中国孩子真实生活/教材场景（教室、操场、家庭、上学路上）。
- 例词只引词库 id：生成时逐词经词库 `word`/`aliases` 解析，解析不到即停改（本波实际改选过：university、chase、news、bless 等不在库，均已换成库内词或改写句子）。
- 不规则变形（sang、went、feet、mice 等）在词库中本身是独立条目（verb_form_of 型），例词直接引其自身 id，不归一到原形——与词库的变形条目政策一致。

### 1.3 病例口径（不自编纪律）

病句医院病例只允许两种来源，均在 `source_type` 中如实标注：

1. **条目登记的事故例**：清单条目正文中以星号或明示「不成立/错误」给出的错形（如 GR-30 的 *My car, that is red、GR-31 的 *more better、GR-34 的 *Here comes it、GR-36 的 *made me to go 所属错误类）；
2. **最小实例化**：条目明确登记为已证实的学习者错误模式（学习者语料或教学文献），用词库词拼出的最小实例（如 GR-11 because…so 并用、GR-22 冠词缺失、GR-42 系词缺失）。实例化只承载已登记的模式，不新造错误类型。

两类都不沾的条目，`error_cases` 一律标结构化 `待补`（status+note），不硬凑。本波结果：**有病例 17 条（共 18 例，GR-32 有 2 例），待补 28 条**（名单见 §5）。

### 1.4 分歧与争议口径

- 专家分歧一律原样登记进 `adult.disputes`，claim 只写清单的呈现口径，不在条目内私了。
- **「汉语形容词都是动词」**（GR-42）：按清单登记状态入模——传统说与 Dixon/Xu 独立词类说并列登记在 disputes 中，claim 只取两派共认的分布事实（汉语性质词可裸作谓语、英语形容词不可），条目不站队改判。

## 2. 本区菜单谓词（语法区）

按设计文档 §5.1 与 WORDBANK 规则 6，语法区的词集不由 GR 条目手工圈定，而由词库字段谓词推导：

| 菜单 | 谓词 | 说明 |
|---|---|---|
| 动词类单元（三单、时态、情态、使役等） | `pos_tags` 含 `v.`（情态 `modal v.` 单列） | 全库动词全量呈现；GR 条目只负责讲解与例证，不圈词集 |
| 名词类单元（复数、所有格、名词短语） | `pos_tags` 含 `n.` | 可数性再按 C 组条目内分类字段细分（C 组波次职责） |
| 功能词相关呈现 | `is_function_word == true` | 与小系统区共用谓词，呈现时按区属过滤 |

GR 组的挂接表（§3）只是**例词级回连**（哪个词在哪条规律里当过例词），与菜单词集是两回事：菜单全量靠谓词，挂接靠例词，两者互不替代。谓词一旦定版，任何词的进出只能改词库标记，不许在视图层增删。

## 3. 挂接表（grammar_hitching.yaml）

- 来源：45 条的 `examples.word_ids` 与 `mechanism.anchors` 实际用到的词，逐词反查词库条目的 `word` 字段落成词形字符串，共 **89 个词形**（如 apple → GR-02/05/12/24；book、play 等高频例词各挂多条）。
- 形态说明：sang、went、feet、mice 等以其自身词形落账（它们在词库中是独立的变形条目）；复合词头条目（be/pronoun 组等）本波未被例词锚点引用，表中无斜杠词头。
- 收官解析（后续波次/校验器职责）：词形字符串 → 词库 id 按 `word` 或 `aliases` 精确匹配回填双向 `law_refs`；本波不动 wordbank.json（纪律）。
